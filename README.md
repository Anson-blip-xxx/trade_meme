# Meme Signal Gate 0.2.0

面向 BSC、Solana、Robinhood Chain 链上资产的信号研究与受控开单服务。研究流程为 **GMGN 买入事件 / 本地画像候选 → 链上来源、安全、钱包资金行为与进场路径 → 可选叙事与社交参考 → 研究结论及限时复评**，由 `ENTRY_MODE` 控制研究结果的开单入口，默认 `off`。

另有独立的 **DeBot / Ave 第三次通知实盘策略**，当前仅处理 Solana：本人在 TG 或 Web 点击“启动计数”，按来源分别计数；第三次通知市值不超过 10 万美元时，经余额、报价、永久防重等开仓核验后自动提交买单及配置的止盈止损。`THIRD_SIGNAL_EXECUTION_MODE=live` 配置这条策略，`ENTRY_MODE=off` 不会关闭它；仅修改配置或收到旧通知不会自动启动实盘。两种策略均未启用时才只研究、不提交买单。

依据官方 [gmgn-skills 客户端](https://github.com/GMGNAI/gmgn-skills/blob/main/src/client/OpenApiClient.ts) 直接调用 GMGN OpenAPI，**不必安装 GMGN CLI**。正式运行需要自己的 `GMGN_API_KEY`，运行入口拒绝公开演示 Key。默认供应商叙事不需要 OpenAI Key。

## 启动

需要 Node.js 24 或以上。在项目目录执行：

```bash
npm ci
npm run setup
```

`setup` 从 [.env.example](.env.example) 创建 `.env`，生成接收令牌且不打印，设置仅本人可读写；已有配置原样保留。编辑 `.env` 填写个人 `GMGN_API_KEY`，先保留：

```dotenv
ENTRY_MODE=off
THIRD_SIGNAL_EXECUTION_MODE=simulation
SCANNER_ENABLED=true
SCANNER_CHAINS=solana
NARRATIVE_PROVIDER=vendor
X_DATA_PROVIDER=fxembed
```

模板已有三条公共主网 RPC，适合初步只读测试；正式使用需检查额度和历史区块、日志查询能力。

```bash
npm run doctor
npm run doctor -- --live
npm run dev
```

`doctor` 检查配置；`--live` 只探测 RPC 网络身份和 FxEmbed 示例帖，不查询报价、不交易、不验证全部依赖。研究配置未就绪时退出码为 1，原因在输出中。缺个人 Key 仍可启动并手工导入，自动扫描等待配置，默认必需的钱包支持保持未知。补齐 Key 不意味着可开单，每个资产仍需实际通过规则和报价检查。

默认服务地址 `http://127.0.0.1:8787`，另开终端运行 `curl http://127.0.0.1:8787/health`。生产构建用 `npm run build`，随后 `npm start`；修改 `.env` 后需重启。

## Web 控制台

界面按观察、研究、运行分为 14 个独立栏目：工作台总览、Meme 动态、实时风控、信号扫描、条件后追踪、榜单研究、每日复盘、持续复盘、钱包画像、前置关联、止盈保护、订单记录、信号来源、运行状态。首页请求 `/dashboard/api/home` 与分页的 `/dashboard/api/signal-counting`，展示服务摘要、第三次通知策略的启停与当前批次；摘要缓存最多 15 秒，不读取完整钱包研究、历史曲线或止盈报价。DeBot 登录放在信号来源，余额和服务器详情放在运行状态。

各列表默认每页 20 条，通过服务端 `limit/offset` 查询当前页并显示总数。扫描支持链、结论、名称/完整 CA 搜索；实时风控支持链和状态，翻历史页固定接收时间边界，避免新信号把记录不断挤到下一页。持续复盘的逐币记录、分组对比和因子验证分开加载并分页。切换栏目取消旧请求，后台标签停止页面轮询，历史页暂停自动刷新；首页不加载隐藏栏目的数据。列表只传摘要，点击记录再读取安全、叙事、钱包路径、机会账本及价格轨迹。

钱包研究默认展示画像分组，也保留公开钱包与前置候选的关联证据、收益、采样涨幅、协同线索和最近观察排序，以及钱包活动、持仓、资金来源和历史统计。浏览器关闭后，服务仍会继续扫描和采样。首页“启动计数 / 停止计数”与 TG 共享策略开关：实盘模式启动后，新的达标通知会自动进入买入流程；停止只关闭新计数与新买入触发，已有持仓监控及平台保护继续。

页面正文采用 16px、表格 14px，辅助文字至少 12px，并随浏览器字号设置缩放。每条扫描和详情均提供 GMGN 代币页快捷链接，按链和完整 CA 生成固定站点地址。顶部常驻系统状况，展示扫描、钱包归档、余额查询及服务器 CPU、内存、磁盘、服务运行时长；详细运行页补充采样时间、进程内存和归档容量。资源每 15 秒本地采样并缓存，打开页面不会触发额外 RPC；CPU 是采样间隔利用率，内存使用量在 Linux 上按 MemAvailable 计算，磁盘指数据库所在文件系统。

设置 `DASHBOARD_ENABLED=true`，`DASHBOARD_ACCESS_TOKEN` 使用独立的至少 32 字符随机口令（不可复用 GMGN Key 或导入令牌）；默认在 `127.0.0.1:9528/dashboard/` 提供页面。当前服务器部署为 `https://43-133-4-231.sslip.io:9528/dashboard/`，沿用 9527 的 HTTPS 证书和登录账户，代理到本机 19538。代理只转发控制台，不能访问交易 API。代理认证后不需要另填 API Key；本机直连可以使用控制台独立口令登录，HttpOnly 会话有效 12 小时。

当前已由 systemd 常驻运行并启用开机启动，单一进程同时管理扫描、采样和控制台。修改配置或静态页面后执行 `sudo systemctl restart meme-signal-gate`；修改 TypeScript 代码先 `npm run build`。查看状态用 `systemctl status meme-signal-gate`，服务定义在 [deploy/meme-signal-gate.service](deploy/meme-signal-gate.service)。已启用服务时，不要再启动第二个 `npm run dev` 扫描进程。

**候选表现的基准是通过研究判断后的第一笔有效 USD 报价。** 使用已验证链上池、Ave 实时行情、DexScreener 批量现价，并以 DeBot、GMGN 独立回退；链、完整 CA、价格时效和同时段分歧必须通过校验，不使用告警旧价或代币历史 ATH。显示 `(已采样最高价 / 基准价 - 1) × 100%`；例如基准 1 美元、后续采样最高 6 美元显示 +500%。这是观测价格变化，不是实际成交利润，也不保证覆盖采样间隔内的最高成交价。界面保留判定时间、基准时间、最新/峰值报价时间、样本数、失败与限流状态。无基准价显示等待/不可用，不显示虚构的 0% 或历史涨幅。

现价观察默认每轮间隔 15 秒、最多 30 个目标；保护中的余仓优先，普通候选与对照继续轮转。Ave 有效推送立即送入保护判断；HTTP 分链批量读取，DeBot 与 GMGN 各自有界回退，GMGN 每轮最多一请求，单一来源的限流不延后整轮。候选多或所有来源缺覆盖仍会延长单币间隔。每个信号从首次符合条件起追踪 24 小时（`PRICE_TRACKING_HOURS`），后续复查不会重置该基准。曾经符合条件后降为观察的信号仍保留在候选表现中；判定过期不等于历史候选消失。监测重启后继续使用持久化基准，不把停机期间的价格补为实测。

新增 `data/scans.sqlite` 只保存页面所需的精简摘要和报价聚合：默认保留 30 天（`SCAN_RETENTION_DAYS`）、最多 10,000 条，单条曲线最多 256 个实际采样点；下采样仍保留基准、峰值与末点。扫描归档可保存最多 12,000 字符的供应商叙事展示文本，并保留来源和更新时间；超限明确标记截断。原帖全文、原始接口响应和凭证不落入扫描归档。钱包归属仍标明供应商/人工线索与未知边界，共同资金来源不等于同一控制人。

余额正常时每 120 秒通过主网 RPC 独立刷新，失败链约 30 秒后单独重试，不提高正常链的请求频率。每次余额查询总预算 8 秒，对短暂网络或服务异常最多补试一次并尊重限流等待时间；错误链和无效数据仍拒绝。失败时有历史成功值则明确标为“上次成功 · 刷新失败”，同时显示成功时间和失败原因；从未成功则显示不可用，不伪装为零余额。这些缓存只供页面展示，实际开单仍要求新的已验证余额。金额上限显示各链原生币总余额的 3%（BSC 用 BNB、Solana 用 SOL、Robinhood 用 ETH），并受费用预留与待结算占用后的可用额度限制；止盈止损展示实际本地配置和已开单的退出状态。

## 自动研究

| 环节 | 实际行为 |
| --- | --- |
| 扫描 | GMGN `/v1/user/kol`、`/v1/user/smartmoney`，每链每路一页；只接受新鲜有效 buy，使用完整 `base_address` 与原交易 `timestamp` |
| DeBot 信号 | 登录后订阅 BSC / Solana / Robinhood 官方频道长连接，每 60 秒补读一页。持久去重，最多并行分析 2 个不同 CA；匿名轮询仅供延迟数据诊断 |
| 控制 | 默认一轮完成后等 60 秒，每轮研究最多 3 个信号。按链/交易/钱包/CA/方向去重；请求和回调串行，去重有 TTL/容量限制，429 服从共享冷却 |
| GMGN 数据 | token info、security、pool、持币者、钱包统计和活动；平台名称、标签、代币描述均为供应商材料 |
| 叙事 | 缺快照时 BSC/Solana 自动按 CA 读取 DeBot v2；最多等待 2 秒，不阻塞必要风控。不是全市场社交扫描 |
| 原帖 | 读取选中引用，同时按完整 CA 搜一页；原帖优先，去重后总计最多 12 条。DeBot 自动取最多 8 条引用，其余来源 ID 保留在临时材料中 |
| 来源 | 核对主网及官方 factory 创建事件，或 Solana 官方程序拥有的派生状态；后缀、Logo、同名、GMGN launchpad 标签不能代替证明 |
| 安全 | GoPlus、Solana 原始 Mint 权限/扩展为主，GMGN 安全字段补充；局部供应商通过不能覆盖主检查缺失 |
| 钱包支持 | 当前持仓、近期买卖和资金关联；默认至少 2 个符合条件的资金关联组支持 |
| 结论 | `BUY_CANDIDATE` 为研究候选，必要数据缺失或模式未适配为 `WATCH`，明确阻断为 `REJECT`。实际执行结果看订单账本 |

有限公开标签钱包样本不等于全市场发现。未来涨幅、`price_change`、金银铜狗、事后 10 倍不作为当前信号，不回填到历史入场特征。

DeBot 配置为 `DEBOT_SCANNER_ENABLED=true`、`DEBOT_TRANSPORT=authenticated_stream`。在 9528 控制台“信号来源 → DeBot 登录”中发送邮箱验证码，并输入邮箱验证码和 Google Authenticator 当前动态码。邮箱由服务器 `DEBOT_LOGIN_EMAIL` 固定配置；两个验证码仅用于当次请求，不存入数据库、日志或浏览器存储。通过官方 `/api/user/info` 验证后，会话原子保存到 `DEBOT_SESSION_PATH`（默认 `data/debot/session.json`，目录 0700、文件 0600）。该凭据文件仅留在服务器，禁止提交到 Git。

2026-10-18 核验官方 [ai-trading-skills 固定版本](https://github.com/debot-ai/ai-trading-skills/tree/9aa1647880c90f03006d3decad97d03b91b188e3)：当前仅发布 `debot-trade`（CLI v0.0.2），使用 API Key 与 Secret，提供绑定钱包、交易、固定止盈止损和交易签名广播；实时行情、钱包监控与 AI 信号仍列为后续开放能力。因此该技能目前不能替代本系统实时信号的会话认证，也未将交易凭据复用到网页接口。其 `buy-tpsl` 卖出比例按原买入量计算，与本系统“按剩余持仓”不同，不能直接复制档位参数。本系统尚未安装或调用 DeBot 交易 CLI。

登录后使用网页当前采用的 Socket.IO `/portal-ws`，先发 `authorization` 并等到 `success`，再订阅 BSC=2、Solana=1、Robinhood=83 三个频道。断线退避重连并重新验证会话；明确失效时停止订阅，提示重新登录，不自动切到匿名信号。授权后及每 60 秒读取一页最近信号用于补数，不跟随历史分页。此为观察到的网页协议，不是供应商公开稳定 API；代码测试不等于真实账号已完成授权，实际状态以页面为准。

精简信号单独存入 `data/debot-signals.sqlite`（最多 30 天、10,000 条任务、10,000 个通知版本、SQLite 主库 64 MiB），冻结首次接收时间、原告警时间、完整 CA 和供应商钱包线索；不保存 Cookie、供应商原响应或事后涨幅。超过 120 秒的初次告警和排队期间过期的信号不送入实时研究。卡片刷新、重启不会重复送交同一事件；分析期间宕机的记录标为中断。页面分别显示订阅授权、信号延迟、研究排队和异常；研究仍受 GMGN 额度限制，断线、队列或页容量可能遗漏信号。

重复提醒按 **链＋完整 CA** 合并展示，保留首次／最近接收、独立通知数、累计投递数及已完成分析轮次。“通知历史”按需读取、每页 20 条，区分重放、展示更新、钱包线索、合并、待核验和实质复评。原样重发仅增加投递次数；价格、名称、顺序或已知地址的别名变化不重复跑完整研究。通知次数不加分、不增加独立资金组，也不改变首次判断、价格基准及长期复盘样本。

新钱包别名仅触发详情核对。只有完整真实地址、有效钱包交易时间或数量的变化，或本地已观测的新交易，才触发复评；供应商变化与本地逐笔证据分开标注，均不证明钱包实际归属。普通重复提醒每币默认冷却 30 秒；已观测卖出风险可以跳过此冷却、优先进入空闲研究槽位，仍执行全部安全和时效门槛。同币分析期间仅保留一个后续任务，合并中间钱包线索，每轮最多读取 6 个通知的详情，每次最多 4 秒；超出范围或部分失败明确标注，不把“没查到”当作“无变化”。最多 3 个有地址的变化钱包进入现有钱包研究预算。

同一个通知改写时间不会刷新原告警。旧卡片只有出现晚于上次研究、且最近 120 秒内的明确交易时间证据，才可据此进行新一轮研究；原始告警时间仍不改写。所有 DeBot 下单路径（包括后续 WATCH 复评）在订单事务内检查同链／CA／执行模式的开仓历史，已有准备、提交、确认、不明状态或模拟仓位时不再次开仓；平仓后重复提醒也不能自动重新入场，明确失败的订单可重新研究后重试。

新信号会请求对应的钱包明细，最多提名 3 个完整非零地址进入既有 GMGN 钱包研究预算，随后核验持仓、统计和活动。别名、盈利榜、供应商钱包数不生成链上交易，不算作独立聪明资金组，也不证明 KOL 归属。缺少地址时继续已有研究流程，不编造地址。DeBot 叙事和平台标签不覆盖合约安全检查。扫描列表标明 `DEBOT` 来源。

收到初次告警后立即并行发起直接安全检查、代币快照和有足够线索的发行来源检查；EVM 缺创建交易时，仅等待代币快照，不再等待全部钱包画像。初次钱包详情最多占用 4 秒，和安全检查并行；完整研究默认最多 30 秒（`EVALUATION_TIMEOUT_MS`），明确安全风险立即终结，超时未完成的关键检查保持 `WATCH`。取消会传递到 HTTP 请求和 GMGN 排队任务，迟到结果不能修改已完成报告。两个不同 CA 可同时分析，同一 CA 互斥。

`MARKET_RISK_REQUIRED=true` 时还需完整 CA/链绑定的 GMGN 池、价格和正流动性数据；错资产、缺字段、数据矛盾及过期结果均不能放行，明确零流动性或已知技术危险拒绝。集中度、开发者持仓、捆绑量和疑似内部钱包比例保留为供应商估计，不把 LP 账户算成已确认庄家，也不把捆绑成交占比当作持币占比。当前市场门槛是已报告池数据的核验，尚未覆盖实际卖出模拟、独立池深和订单价格冲击，不能解释为保证买卖成交。

必要的安全、来源、钱包及市场证据最长有效 120 秒；DeBot 信号以原告警或经上述核验的新交易时间限制 120 秒，结论有效期取这些期限与候选 TTL 的最早值，开单入口再次检查。9528 独立的“实时风控”栏目在最新页每 2 秒读取精简进度，展示信号延迟、排队、分析耗时及检查原因；单项通过不代表可买，全部必要判断完成且未过期才显示研究候选。页面隐藏、翻阅历史页或切换视图时暂停读取。

实时风控以列表展示币名、符号、完整 CA 的缩写、链标、百分制核验分及原始结论。`risk-evidence-v1` 分配合约安全 30 分、发行来源 15 分、市场数据 15 分、钱包支持 40 分；通过项目得对应分值，未知或未通过项目不计分。明确硬风险或 `REJECT` 将总分归零；未完成标暂评，过期保留历史分并标记。悬停或聚焦分值可查看各项得分与原因。评分只是已有核验结果的展示，不是胜率、收益预测或新的开仓门槛，不改变买入资格。名称仅从完整链/CA 已绑定的 DeBot 元数据、GMGN 快照或已有本地扫描档案补齐，不为显示名称增加上游请求。

`anonymous_poll` 仅保留作诊断模式，匿名告警有供应商延迟，不能视为实时。默认不启用该模式。登录方式、信号字段或权限变更会在控制台显示固定错误码，需要重新核对网页协议。

### Meme 动态：独立持续观察

9528 新增 **Meme 动态** 栏目。安全核验决定是否满足研究准入；动态机会分描述当时观察到的变化，两者分开。新 DeBot / GMGN 信号进入独立观察池，不再等到 `BUY_CANDIDATE` 才开始积累。重复通知不直接加分，也不重复生成一个独立代币样本；重启保留首次登记时间和已有判断。

`meme-research-v1` 记录市场活跃度（30）、交易情绪代理（25）、钱包接力（25）、叙事与传播证据（20）。具体依据包含成交活跃与加速度、持有人和流动性变化、买卖金额或笔数压力、采样高点回撤及恢复、真实钱包交易与画像支持/撤退、取得的 CA 帖子作者和时效、名人关联层级。阶段可随新证据变为升温、加速、分歧、拥挤或退潮；这是一套待校准的研究规则，分数不是胜率。单个池的笔数不等于全币资金流，链上交易也不等于社交情绪；付费推广、通知次数、供应商 AI 评分与引用 ID 数量不会冒充自然热度。

缺失维度显示未知，并同时显示已测覆盖分值，**不把仅有的维度放大到满分**。只有足够新鲜的可比样本才给总分；薄流动性或极端集中度会限制研究分值。同源、同池才比较价格和流动性，切换池或供应商重建窗口，不拿供应商 ATH 补历史。项目方填入的名人主页仅提供微弱研究优先级，不能成为名人背书；帖子需核对作者身份、完整 CA、时间和原文证据。

BSC / Solana 使用 [Dexscreener 批量代币接口](https://docs.dexscreener.com/api/reference) 每批最多 30 个 CA，只选与 baseToken 精确匹配的一个池。采样任务每轮完成后等待 5 秒，每币目标间隔至少 30 秒；缺报价时每批最多一个 GMGN 只读后备请求，共享现有限流队列。Robinhood 仅走后备读取，不能保证同样频率。默认同时观察最近两小时的最多 180 个币，超量明确标为等待；120 秒未取得有效价格显示过期，不能把历史评分看成当前可买。

叙事读取独立于快速风控，每个任务最多 12 秒，单币重试至少间隔 10 分钟、全局串行排队；供应商失败后仍在预算内尝试原帖。来源时间、获取时间、原帖覆盖和失效状态留存。没有 X 搜索凭据时，按既有链接/引用取得的帖子只是局部样本，不能声称已经掌握全网舆情；缺失仍不阻断原有安全研究。

每次判断保留当时特征、规则版本、各项分数和变化原因。详情把判断后 5 分钟、15 分钟、1 小时的同池采样价格变化单独列出，仅使用目标时刻后两分钟内实际采到的价格；尚未成熟、缺报价或池不一致显示未知。这些是后验观察，不是交易收益，不回写旧评分，也不会把同币几百次提醒当几百个成功案例。当前提供持续积累和可复盘的前瞻样本，尚未自动训练/替换权重或接入交易触发。

观察配置为 `MEME_OBSERVER_ENABLED`（缺省随 `DEBOT_SCANNER_ENABLED`）、`MEME_MAX_ACTIVE=180`、`MEME_ACTIVE_WINDOW_SEC=7200`、`MEME_DATABASE_PATH=data/meme-observations.sqlite`、`MEME_MAX_MB=1024`。行情/判断最多保存 30 天或最近 250,000 条，催化历史最多 20,000 条，先到上限者生效；研究库达到配置字节容量的 80% 时，按最旧快照分批回收到 70%，每轮最多删除 10,000 条；未回收足够空间时暂停新采样并显示空间保护状态，后续继续清理。SQLite 空闲页复用，不执行整库 VACUUM。此库与长期钱包画像库独立。列表和历史默认每页 20 条，按需读取，首页不加载观察历史。新动态层本身仅研究，不提交订单；独立第三次通知策略的实盘状态另行控制。

### 叙事与证据

当前使用用户提供并匿名只读验证过的网页接口：

```http
GET https://debot.ai/api/v1/nitter/story/latest?request_id=<UUID>&ca_address=<完整CA>
```

这是观察到的网页接口，不是已确认稳定的公开开发者协议。字段变化、认证要求、限流或无结果时叙事参考标为不可用，不单独阻断成为买入候选；不自动登录、取 Cookie、绕过验证、切换模型或购买服务。自动读取仅支持 BSC/Solana，Robinhood 链范围未确认。

**DeBot 分数 2、负面评价或“不建议关注”不会单独拒绝，高分也不直接放行。** `rating.score/reason` 仅供参考，满分未知，不归一化、不设阈值。缺失快照、普通复制文字、无法核实的引用以及模型观点均只作叙事参考；来源、安全、钱包等其他硬门槛通过后，叙事缺失不再导致 `WATCH`。明确的链 / 完整 CA 身份冲突仍阻断，防止把另一资产的材料套用到当前币。

结构化材料检查要求起源材料、有效生成时间、完整 CA 与链对应、引用映射及实际取得帖子覆盖。至少一名追踪作者或两名不同公开作者可满足作者覆盖；不同作者不保证独立。通过仅表示材料与资产的关联得到核对，不证明供应商观点、名人背书或收益；`claim=official` 仍需额外身份依据。

证据记录 URL、数值作者 ID、发布时间、抓取时间和渠道。FxEmbed/TwitterAPI.io 标为第三方副本。`narrative.facts.evidenceDiagnostics` 区分 lookup/search 的成功、无结果、缺 Key、不可用；一页搜索不证明全网传播量，供应商来源 ID 列表不等于已经读取全部帖子。

### 限时观察与自动复评

`WATCH_RECHECK_ENABLED=true` 启用持久复评队列。`WATCH` 的同一行会在后台重新检查来源、安全和钱包条件；叙事仍可获取，但不再是必需材料。默认全局每轮最多处理一个到期任务，完成后至少等 120 秒，复用 GMGN 的请求队列和限流冷却。任务已到期但扫描繁忙时，每 10 秒只检查本地忙闲状态，空闲后接续该轮，避免两个定时器反复撞在忙时；供应商限流仍按正常间隔等待。网页显示待复评、排队、复评中、观察结束及对应时间。浏览器刷新只读取状态，不触发研究请求。

截止时间取首次接收加 `WATCH_WINDOW_SEC` 与原信号发生加 `MAX_SIGNAL_AGE_SEC` 的较早者，默认最多 10 分钟。重新检查不刷新原始事件时间，也不续期；超过截止的结果不触发下单。新信号接替同币旧任务，每条链 / CA 同时最多一个活动任务，处理租约与截止跨重启保留。旧版本只存了摘要、没有最小原始信号的记录显示观察结束，不伪造一个新起点。安全和来源通过且钱包条件满足后成为候选，明确阻断则结束为排除。

### 叙事展示与名人社交参考

扫描列表展示两行叙事摘要；鼠标悬停、键盘聚焦或手机点击可打开可滚动全文，显示供应商及原始更新时间。缺失显示暂无参考，不因缺少叙事强制等待。内容按文本渲染，不执行供应商 HTML。

名人注册表为 `config/social-profiles.json`，当前涵盖 BSC 的 CZ / 何一及 Solana 的 toly / Elon。只读取已绑定正确链与 CA 的 GMGN `info.link` 字段；精确匹配名人主页或含账号名的帖子链接，按每人 **+5**、此类合计最多 **+10** 作为项目资料线索。仿冒域名、相似账号名、AI 文本提名不计分，也不认定名人背书。

已取得的帖子只有在作者数值 ID 与经过核实的注册表匹配、正文包含完整 CA、时间有效时，才可按每人 **+20** 计分；同人不与主页分重复叠加，总分最多 **30**。当前内置注册表只核实了主页 handle，数值 ID 尚未获得可确认的身份来源，故这些账户目前只启用弱链接加分，不假装已经核实名人发币或喊单。第三方帖子副本保留第三方标记。

分数仅影响已到期复评任务的研究排序：最多获得相当于 30 秒排队时间的优先，不跳过原定复评时间、信号截止、合约安全或钱包门槛，不增加买入金额。

### 钱包与资金行为

普通大户和 `smart_degen` 持币者各请求一页、最多 20 条，去重后默认补充 3 个钱包的 7 日统计与该币活动，可配置 1–5 个。近 1 小时净买入来自实际买卖事件，累计买入金额、历史收益、曾经买过不等于近期流入。

活动仅取一页并记录分页覆盖。页已结束或已覆盖窗口起点、且金额/时间有效，才认为窗口覆盖；缺页保留未知。合格支持要求当前持有、研究完整、近期净买入为正，并排除已发现的开发者关联、捆绑/疑似内幕标签、冲突等风险组。

GMGN 标签不证明真人身份；共同资金来源仅是关联线索，不证明同一持有人。交易所公共出金源不按同一操盘主体合并，关联组数只是独立参与者数量上界。`WALLET_IDENTITIES_PATH` 可指定维护者 JSON 数组，字段为 `chain/address/label/entityId/category/reference`，见 [类型定义](src/research/wallet-types.ts)。公开归属要求 HTTPS 来源，自定义用 `operator_defined`；均标记人工提供、未独立核实，不接受普通信号传入身份断言。

### 长期钱包观察库

`WALLET_RESEARCH_ENABLED=true` 启用独立的 `data/wallet-history.sqlite`。关闭浏览器、禁用控制台、研究结论为 `WATCH/REJECT` 或内存缓存过期，都不会停止或清除钱包归档。保存的是规范化交易证据、持仓、资金来源、供应商收益统计和报价；不复制原始接口响应、API Key、叙事全文。地址按链隔离，EVM 地址统一小写，Solana 保留大小写。交易在可用身份字段范围内去重，不把多次轮询当成多笔交易；缺事件索引时标明交易内歧义。

数据入口包括：

- 扫描器已取得的 KOL / smartmoney 买卖页在候选筛选之前归档，包括未进入每轮深入研究额度的交易，不额外请求这些页面。
- 所有完成的真实研究归档持仓、资金来源、近期交易和 7 日钱包统计；演示报告不进入长期库。
- 独立观察器读取涨幅榜，交替选择榜上代币和最久未刷新的已观察代币，查询该币盈利交易者、当前报价与钱包活动；盈利交易者不限定 `smart_degen` 标签。

默认观察器每轮结束后等待 300 秒，一轮最多 9 个只读请求、轮转一条链，和扫描器共用 GMGN 请求队列与限流冷却。每条链交替执行市场研究与公开钱包关联调查；没有近期目标时继续观察已有有效关系，两者都没有时回退市场研究。市场研究在持币者页面最多深入补充 1 个钱包；交易者单页扩大至 100 条，在利润、未实现利润、买入量和卖出量四种正式排序间轮转。优先补查较少研究的钱包，再交替参考利润顺序和首次获得代币时间，采集真实活动与 7 日统计；早期候选活动按当前代币筛选，首次获得时间不能代替买入证据。请求次数与权重预算保持原规模。调度游标及各链未完成目标持久化，限流、失败和重启不会把未完成调查当成完成，失败链也不阻塞其他链。三条链均启用时，关联轮次约每链 30 分钟一次，另加实际请求耗时与冷却；代币和候选钱包还会轮换，并非每个钱包都每 30 分钟覆盖。样本量、接口限流和请求耗时会影响覆盖及刷新间隔；这不是全链流水或完整历史回补。失败页面也记录采集缺口。榜单是发现观察目标的入口，不能倒推系统在涨幅发生前就已发现它。

收益榜使用**最新可用的供应商整钱包 7 日已实现收益**；不同日期的滚动窗口不能相加。单币累计收益单独展示，不能与整钱包收益混排。涨幅榜使用**本系统观察到买入后，首次有效报价到后续最高采样价**的变化，基准与峰值跨重启保存，不使用历史 ATH，也不表示该钱包实际买价、卖价或实现利润。未采到报价时保持未知。

外部研究名单已接入 [oooooyoung EVM 地址清单](https://github.com/nopapername/oooooyoung/blob/2bae0bcfe62d4a32e11e5368fef37e5abf5d6f50/oooooyoung%20evm%E8%81%AA%E6%98%8E%E9%92%B1.json)：固定提交 `2bae0bc`、SHA256 校验的本地快照，449 个去重有效地址。启用钱包研究时幂等导入独立名单表；原标注、来源与分组只是未核实线索，不写入身份映射、KOL 标签或聪明资金资格，也不生成交易、画像、独立资金组或开单加分。列表和详情按完整地址关联展示，BSC 与 Robinhood 的行为证据仍分别积累，同地址不证明跨链同一控制人。更新名单需重新核对并固定版本，不在启动时拉取可变远程内容。

名单研究复用原观察器预算：每条 EVM 链最短间隔 30 分钟，每次最多消耗一个钱包活动页请求；每链四轮至多一轮用于名单，保留完整的正常市场轮次与关联研究，不打断尚未完成的目标。三链、300 秒轮询时约每链一小时才轮到一个名单地址，接口冷却可能进一步延迟，并非实时覆盖全部 449 个地址。已有本链买卖证据者优先轮转，BSC 可逐步探查尚未观察的名单地址；Robinhood 只补查已有该链买卖记录者。返回的交易经原有链/地址/时间校验、去重后进入既有画像与前置关联流程；标签本身不会替代事实。钱包研究状态展示导入来源、各链匹配覆盖、最近探查与错误，浏览器关闭仍持续执行。

协同线索记录共同非公共资金来源、相近时间同方向交易及具体对象。同步条件为 120 秒范围内至少两笔不同交易，使用有限近期样本；交易所公共来源、冲突资金来源不作为共同控制证据。列表分数只是观察优先级，不能认定“阴谋盘”或实际控制人。排名分页使用持久聚合，协同计算分批刷新；列表与详情可能存在刷新延迟。

该库**不按天过期，也不为腾空间删除旧研究**。默认容量上限 512 MiB（`WALLET_HISTORY_MAX_MB`，包含数据库与 WAL 文件），接近上限时停止追加并在页面明确告警；已有记录仍可读。调整容量后重启可恢复追加。可通过 `WALLET_OBSERVER_INTERVAL_SEC`、`WALLET_OBSERVER_MAX_REQUESTS` 调整采集预算。备份运行中的 SQLite 请使用 SQLite 在线备份方式，不要只复制主文件而漏掉 WAL。

当前服务器已于 2026-10-09 启用长期采集，容量配置为 8192 MiB，导入了当时尚在缓存中的规范化研究。协同索引每 10 秒处理一小批钱包，每个钱包之间把执行权交还 HTTP 和监听回调，不并发叠加批次，无额外网络请求；尚未计算显示“待分析”，历史结果待重算显示“待刷新”。网页关闭不影响这项工作。

### 持续钱包画像与分组

新增独立的“榜单研究”，持续关联上榜代币、实际买入引用、已记录信号和含完整 CA 的原帖时间，并分别积累已实现盈利、未实现浮盈亏及跨币表现。区分当时已观测与回溯补录，不把持仓起始时间、AI 叙事生成时间或盈利榜名次当作叙事发现能力。历史回填与新证据轮转在独立 worker 中执行，页面按需加载且分页；详见 [榜单研究的证据口径、配置与接口](docs/token-rank-research.md)。

钱包观察库启用时，默认同时启动独立工作线程，把派生画像保存在 `data/wallet-profiles.sqlite`。首次按持久游标逐批覆盖历史钱包，之后持续处理新增钱包、更新的数据及过期画像；不依赖浏览器访问，也不新增 GMGN 请求。链上监听库的交易参与、转账会进入画像，但不会被自动解释为买卖或持仓。原始研究库和链上库只读，画像计算不在扫描 / WebSocket 的主线程运行。页面共享的钱包总量统计缓存 30 秒，并返回 `statsComputedAt`，避免多个视图重复扫描历史表。

分组可重叠：公开 KOL 标记、前置候选、跨币重复前置、前向验证、共同资金来源、同步交易、供应商近期报告正利润、观察后采样上涨至少 100%、样本不足、采样活动超过 7 日未更新。前向验证要求关系先被系统发现，再观测候选买入，随后出现公开钱包买入；补查历史不会变成提前发现。已知公共出金源不作为资金同源分组依据，链上参与次数不作为盈利证明。

每个画像保留计算时间、证据时间、首次入组时间、依据和入组 / 退组历史。新证据、供应商利润过期或底层关联待重算，都会影响分组；新证据立即入队，无变化画像按配置周期核对，利润将在其 24 小时有效期到期时提前排队。排队延迟会显示为过期，而不会冒充已刷新。分组历史首次时间指本系统实际建档时间，不追溯到过去的交易时间。关系图仍属于待核查线索，不能认定同一控制人或真实收益。

`WALLET_PROFILES_ENABLED` 未设置时跟随 `WALLET_RESEARCH_ENABLED`；显式设为 `false` 可停用。默认每批结束后等 2 秒，目标批量 100（部分数据源补充可能略多），由 `WALLET_PROFILES_INTERVAL_SEC` / `WALLET_PROFILES_BATCH_SIZE` 调整。来源游标会立即重算发生变化的钱包；无变化钱包只按 `WALLET_PROFILES_REFRESH_AFTER_SEC=21600`（6 小时）做周期核对，避免反复扫描整个历史库。上限 `WALLET_PROFILES_MAX_MB=512` 包含数据库及 WAL，达到容量时停止派生写入并告警，保留已有画像；增加容量后重启恢复。首次补建需要时间，控制台“钱包研究 → 画像分组”显示覆盖数量、分组数量、陈旧画像和运行状态。

只读且需要控制台认证的 API：`/dashboard/api/wallet-profiles/status`、`/dashboard/api/wallet-profiles?chain=bsc&group=repeated_early&limit=25`、`/dashboard/api/wallet-profiles/:chain/:address`。详情包含最近 20 次分组变化；完整变化记录仍在本地数据库。画像经下述钱包路径筛选参与信号研究，分组标签本身不直接授权开单。

画像另做**有向行为比较**，防止把跟单者当成公开钱包的关联小号。先从候选钱包最近最多 500 条活动中选择最多 30 个买入合约，再按共同合约数选最多 4 个公开标记钱包；选择过程不看谁先买。对所选合约，双方的最早已知买入重新从本地历史表查询，并检查跨来源时间冲突，避免只拿最近一页或历史赢家片段。每对钱包独立统计提前、跟随、近时不明、超过 24 小时比较窗、未匹配。相同交易、两秒以内和时间冲突不确定先后；未匹配表示采样没有记录，不表示对方没买，也不是预测失败。

至少 3 个不同合约、同一方向占全部共同合约 75% 才形成“前置模式样本”或“跟随模式样本”；提前和跟随各至少 2 个且均非主导时为方向混合。同币反复交易不增加独立样本数，跨对手的钱包次数也不能拼接。共同合约分母包含近时不明与超窗记录；页面另显示候选合约总数和未覆盖数。因此“3 次提前、20 次跟随”会保留为跟随模式，不因早买赢家片段变成前置模式。这些是尚未校准置信度的研究门槛，不能解释为命中率或身份概率。

角色详情保留反例、其他可能解释以及每对最多 6 条代表证据。资金线索独立展示，不能改变方向结论；已知公共服务、冲突来源和本地样本中连接超过 20 个接收钱包的高连接度来源不支持同源分组（这不等于已证明该来源是公共服务）。直接注资仍只是联系，公开钱包之后的一笔卖单也不等于出货获利。现有“历史重复提前”可聚合不同对象，仅保留为历史线索；角色判断以逐对比较为准，所有权始终未知。

有向比较随原画像后台批处理执行，没有新 GMGN 请求。旧画像通过索引逐批补算，状态含 `roleProfiles/rolePending/roleLastRunAt`。同一输入至多复用 10 分钟的比较结果，再由画像更新或到期轮转重算；缓存时间不会延长旧角色的有效期。新增筛选为 `follower_pattern/precursor_pattern/mixed_pattern`，变化同样保留入组、退组记录。画像中的前向观察数只表示已有验证记录；新机会另存持续账本，两者均不报告预测命中率。

### 钱包画像接入 Meme 筛选

信号研究同时检查两条钱包路径，满足其一可提供钱包支持依据，并参与复评优先级排序。原有明确失败的资金检查仍会阻断，发行来源、合约安全及信号时效要求继续生效；画像标签或盈利榜名次不能单独使代币通过筛选。该研究入口在 `ENTRY_MODE=off` 时不提交交易，独立第三次通知策略另行控制。

| 路径 | 当前研究条件 |
| --- | --- |
| 前置钱包买入 | 候选相对该公开钱包的前置模式，在本次买入前已经记录；至少有 3 个其他代币的领先证据，相关交易及本地取得时间均早于本次买入。后补画像或历史买入不能冒充提前发现。 |
| 公开钱包直接进场 | 公开标记钱包直接买入后，至少观察到 2 个其他买入组；每组需有当前分析中的有效持仓及至少一笔 100 USD 买入，排除已减持、转出和冲突记录。已知相同资金联系会折叠，疑似与触发钱包同组的买入不用于凑数。组数不是独立参与者人数，也不证明真实跟单。 |

两条路径共同要求：最近 10 分钟内有至少 100 USD 的有效买入；相关画像未过期；公开钱包的供应商 7 日已实现利润快照不超过 24 小时，利润至少 1,000 USD，且在同链至少 10 个有效正利润钱包样本中达到第 75 百分位。盈利分位仅针对本地有效样本，供应商利润并非本系统核算的实际收益。

还需取得有效的当前持仓、完整覆盖的近期净买入及报价；相对触发买入报价的变化必须在 -20% 至 +40% 内。买入金额或报价缺失、持仓与活动覆盖不足、已发现的风险或开发者关联，都保留为缺口。候选或对应公开钱包出现卖出、转出、无持仓或冲突证据时，可撤回该路径的支持；卖出记录本身不代表清仓或获利。上述数值是初版研究门槛，0–20 优先级不是概率、胜率或身份认证，所有钱包归属仍为未知。

服务每 10 秒从本地历史轮转核对最多 10 个待观察代币；本地画像候选最多每分钟触发一次常规信号研究，并服从已有忙碌状态及限流冷却。组合已采集的画像、交易和报价不另发供应商请求；触发常规研究仍会使用现有 GMGN 请求队列与配额。轮转采样可能延迟，不是全钱包实时监控。

开单链路在报价及提交等待前后重新读取本地钱包反证。原先依靠画像形成的候选，必须仍由同一条已登记路径提供支持；新卖出、冲突、资料缺失或过期都会阻止使用旧判断。该复核不增加供应商请求，不能覆盖本地尚未采到的交易。

### 钱包机会持续账本

符合登记条件的前置与公开进场线索写入独立 SQLite 账本，冻结首次判断、触发交易、画像时间、盈利快照、支持依据和反例。后续复评不改写首次证据，支持撤回另存；扫描详情分别展示“当时判断”和“持续观察账本”。后续公开钱包买入必须在实际登记之后发生，且在登记之后被本地取得；补查登记之前的交易不算预测兑现。

每条机会观察 24 小时，分别记录等待公开钱包、直接进场、已观测后续进场、卖出或转出及到期关闭。前置路径到期仍无确认记录时标为“到期未确认”，不会按预测失败计分；已经确认的进场或减持事实保留。冲突记录及采样截断会明确显示，缺失数据不能换算成胜率。

`WALLET_SCREENING_ENABLED` 未设置时依次继承 `WALLET_PROFILES_ENABLED`、`WALLET_RESEARCH_ENABLED`，需要钱包研究库及画像模块同时启用。`WALLET_SCREENING_DATABASE_PATH` 默认是钱包历史路径加 `.setups.sqlite`；`WALLET_SCREENING_MAX_BYTES=67108864` 默认限制为 64 MiB，达到容量后停止登记新机会，保留旧记录。鉴权只读接口为 `/dashboard/api/wallet-screening/status` 和 `/dashboard/api/wallet-screening?chain=bsc&address=完整CA&limit=20`。

### 公开钱包与前置候选关联

以 `gmgn_kol_feed` 的公开钱包买入为调查入口，寻找其已记录首次买入之前 24 小时内买入同币的钱包。每个公开钱包 / 代币组合最多分析 400 条买入、40 个候选；按不同代币累计重复领先，不把同币反复交易算成多次跨币验证。同一钱包、同一交易、同一时间的记录不形成领先关系。后续发现公开钱包更早买入时，会撤销不再成立的派生时序，保留原始规范化证据。这里的公开买入时间**不是已核实的 X 喊单时间**，本地首次观测也不是完整历史首买。

发现新关联的轮次在原有 9 请求额度内采集两页不限制聪明钱标签的交易者（买入量、卖出量各最多 100）、代币报价，以及公开钱包和最多两个候选的活动与 7 日资料。已清仓者也可成为候选。新候选使用单币活动核查真实买卖时序；已建立关系的候选使用整钱包最近活动页，积累它在其他币上的新交易。每第三个关联轮次优先持续观察已有关系，直接读取候选与公开钱包的整钱包活动和资料，不因原代币超过 24 小时而停止；候选关系的轮换时间持久保存。交易量排名只用于候选发现，不能当成盈利排名或首买证据。当前接口没有接入全币完整流水，低交易量钱包、分页以外事件、通过多跳转移的资金关系仍可能遗漏。

每条关系保留逐币 CA、交易标识、交易时间、本地取得时间及首次发现关系时间，并分开统计：

- **事后回溯**：公开钱包买入后，系统才取得候选的历史买入记录。
- **提前观测**：公开钱包买入前，候选的买入记录已经进入本地库。
- **后续验证**：该关系在候选这次买入前就已建立，且候选交易提前被本地观察到；历史补查不能充当后续验证。

附加记录公开钱包买入后 24 小时内的候选卖出，以及直接注资、共同非公共资金来源；资金联系明确标记实际取得时间和 `vendor_claim`，不追溯为历史当时已知的证据。识别为公共服务或存在冲突的来源不支持归属推断。这些是待核查关系，不证明同一控制人、内幕交易、真实盈利或未来收益。新索引在原长期库内持久化，启动及每 10 秒分批处理，不新增网络请求，也不改变开单门槛。

只读 API：`/dashboard/api/wallet-associations` 支持 `chain/search/limit/offset`；`/status` 返回回填进度；`/:chain/:leader/:candidate` 返回有方向的逐币证据和资金线索。与原控制台共用认证。

## 链与平台

| 链 | 来源路径与边界 |
| --- | --- |
| BSC | Four/Flap 官方创建事件；可提供 `creationTx`，用 Etherscan Key 查创建交易，或用 GMGN 创建时间作有限 RPC 查找提示 |
| Solana | Pump Mint 派生 bonding-curve PDA；Bonk LaunchLab PDA、独立 platform config、Mint/报价资产对应，不单看 Program ID |
| Robinhood | 已登记官方 Flap 主网 Portal，核验 chain ID `4663`，不复用 BSC factory。自动 DeBot 叙事不支持，但叙事缺失不单独阻断；可导入明确绑定该链的材料供参考 |

EVM 查找先从最新区块向前扩大定位范围，再在范围内二分，最多读取 40 个定位区块；搜索前后 128 个区块、每段最多 64 个。近期代币不依赖远古区块数据。找到日志后仍检查完整 receipt、交易状态、CA、官方发出者、至少 12 个后续区块、规范区块及 runtime code。时间提示错误、历史 RPC 不支持或限流保持未知，不扩为全链扫描。

BSC 模板使用 `https://bsc.rpc.blxrbdn.com`，已用真实代币验证创建日志与回执查询；公共节点仍可能限流。BNB 默认 dataseed 不支持 `eth_getLogs`，不能用于这里的创建日志查找，依据见 [接口核对记录](docs/sources.md)。

Flap legacy/V2 非税已知模式可进入后续检查；税版本、未知扩展和未适配版本保持 `modeSupported=false`。Pump/Bonk 同样仅支持已实现布局与模式。官方来源不等于安全、项目官方身份或名人背书。见 [平台注册表](config/platforms.json)。

## 手工导入

格式见 [标准信号](fixtures/signal.example.json)、[通知包装](fixtures/notification.example.json)。通知解析完整 CA 和 X 原帖链接；链和原事件时间显式提供，多 CA 用 `address` 选择。人工副本不是供应商验签 Webhook。

```bash
npm run analyze -- path/to/signal.json --normalize-only
npm run import -- path/to/notification.json --normalize-only
npm run analyze -- path/to/signal.json --text
npm run import -- path/to/notification.json --text
```

`--normalize-only` 只解析。普通 `analyze/import/import-debot` 会研究并执行当前开单策略；当前 live 入口因无人值守退出能力未核实而阻断，不能靠切换环境变量绕过。其独立内存缓存退出即清空，报告 ID 不会出现在另一个已运行服务里；需持续查询和重试时，通过 HTTP 导入服务。

[真实 Umi 快照](fixtures/debot-story-v2.example.json) 保留中文 13 节和 38 个推文 ID，仅移除英文、日文翻译。`generated_at=2026-10-08T06:31:41.032Z` 是叙事版本时间，不是已知告警时间。以下命令离线查看，不创建信号：

```bash
npm run inspect-debot -- fixtures/debot-story-v2.example.json bsc 0xc24f42b1e458251e3a128b74c65c4c7fa0c97777 https://debot.ai/token/bsc/248286_0xc24f42b1e458251e3a128b74c65c4c7fa0c97777
```

`POST /v1/debot/stories` 或 `import-debot` 接收包装，下面是结构模板，尖括号和注释需替换：

```jsonc
{
  "token": {"chain": "bsc", "address": "<完整CA>"},
  "sourceUrl": "<对应币种的DeBot HTTPS页面或受支持接口URL>",
  "occurredAt": "<原告警真实ISO-8601时间>",
  "payload": { /* 完整 code / success / data 响应 */ }
}
```

```bash
npm run import-debot -- path/to/debot-import.json --normalize-only
npm run import-debot -- path/to/debot-import.json --text
```

不要把历史事件时间改成当前时间，`generated_at` 不能替代 `occurredAt`。手工副本标为 `user_supplied`，自动取得响应标为 `vendor_endpoint`，均不代表观点已核实。

## 开单与订单状态

| `ENTRY_MODE` | 研究筛选入口的行为 |
| --- | --- |
| `off`（默认） | 研究筛选不创建新开单；独立第三次通知策略由自己的模式与启停状态控制 |
| `paper` | 研究规则通过后取真实 GMGN 报价，记录 `paper_open`；不提交 swap，不模拟成交或盈亏 |
| `live` | 研究入口仍要求其内部退出能力校验；不能用此变量替代第三次通知策略的本人启动 |

`THIRD_SIGNAL_EXECUTION_MODE=live` 单独配置第三次通知实盘入口，默认 `simulation`。当前实盘只允许 SOL，每次新通知续期 6 小时，DeBot / Ave 分开累计，第三次市值须大于零且不超过 $100,000。本人点击 TG / Web“启动计数”才开启新的实盘批次，旧模拟通知、旧指令和旧候选不会补发买单。每单最多使用核验 SOL 总余额的 3%，已开过或已占用实盘开仓的同链 CA 永久不重开。完整规则见 [第三次信号计数与永久防重](docs/third-signal-counting.md)。

paper/live 均需个人 Key，以及相应链的 `ENTRY_WALLET_BSC/SOLANA/ROBINHOOD`、`ENTRY_INPUT_TOKEN_BSC/SOLANA/ROBINHOOD`；余额比例 `ENTRY_BALANCE_BPS_*` 默认 300 基点。链上金额与费用采用最小单位的正整数字符串，不是美元或人类可读币数。按 [GMGN 交易说明](https://github.com/GMGNAI/gmgn-skills/blob/main/skills/gmgn-swap/SKILL.md) 核对地址与账户权限。

三条链均配置 `ENTRY_BALANCE_BPS_BSC=300`、`ENTRY_BALANCE_BPS_SOLANA=300`、`ENTRY_BALANCE_BPS_ROBINHOOD=300`（未配置时也默认 300 基点，即 3%）。仅使用 BSC 的 BNB、Solana 的 SOL、Robinhood Chain 的 ETH；每笔本金为 `min(floor(核验原生币总余额 × 3%), 核验余额 - 其他订单未覆盖占用 - 本单费用缓冲)`，按原子单位向下取整。总余额指该链交易钱包中的原生币余额，不包含 meme 持仓估值；金额比例覆盖旧 `ENTRY_AMOUNT_*`，不再受 0.15 BNB、1 SOL 或 0.05 ETH 固定上限限制。例如 20 SOL、无其他占用且费用预留 0.02 SOL，计划本金为 0.6 SOL。资金占用与费用核算在数据库事务中完成，多个同时到达的候选不会超额预留。

预算分配在 SQLite `BEGIN IMMEDIATE` 事务内完成，报价和提交都使用锁定金额；并发及纸单占用参与下一笔的剩余预算。金额不足一个最小单位、余额接口失败、单位不明或快照过期时跳过，不回退固定满额。这里的余额是该链原生币资金，不含其他代币的估值。

`ENTRY_FEE_RESERVE_BSC/SOLANA/ROBINHOOD` 为每单费用缓冲，默认 **0.005 BNB、0.02 SOL、0.002 ETH**（配置同样使用最小单位）。这些是运营预留，不是实时费用估算或未来卖出费用保证。在途订单及结果未知订单保留本金与费用占用；仅供应商报告成交仍不释放，需 RPC 证明当前余额快照已包含该笔至少 12 块确认的 EVM 扣款，或 finalized 的 SOL 扣款。覆盖证明的快照高度记录在开单明细，下次仅对不低于该高度的余额复用。纸单不虚构链上扣款，持续占用其模拟本金与缓冲。

live 在报价后、发送队列内再次读取余额并核对已预留金额；若原报价超过最新原生币总余额的配置比例，以 `ENTRY_BALANCE_FRACTION_EXCEEDED` 停止提交；若无法同时覆盖本金、其他占用和费用缓冲，则报告余额不足。余额上涨不放大已报价金额。RPC 完成后重查候选时效并生成签名时间戳。旧订单若未记录比例基准，继续按创建时的“扣除费用与占用后的可用余额”基准核验，避免变更历史订单授权金额。钱包被其他应用同时支出仍可能影响成交，此检查不会锁住链上钱包。

live 另需 `GMGN_PRIVATE_KEY`，或用 `GMGN_PRIVATE_KEY_FILE` 指向已有本地签名文件：与 GMGN 配置配套的 Ed25519/RSA **API 请求签名 PEM**，不是钱包助记词或链上私钥，仅用于本地请求签名。非空内联 PEM 优先。报价为 `GET /v1/trade/quote`；开单和查询分别为签名的 `POST /v1/trade/swap`、`GET /v1/trade/query_order`。实际权限和目标资产可成交性仍需个人账户联调。

默认 `ENTRY_MAX_OPEN=3`、`ENTRY_SLIPPAGE_PCT=5`。开单前、报价后和发送前重查时效；研究入口继续要求来源、安全及必需钱包支持，独立第三次通知入口使用已提交的当次通知与当前批次核验，不把历史研究评分当作第三次触发。订单持久幂等阻止重复事件和同链同资产重复开单。发送后结果不明记 `unknown`，不自动重发 swap。

个人 Key 和签名 PEM 已配置时，服务启动及每 30 秒轮转查询最多 3 条有供应商订单 ID 的待确认订单、已确认但成交金额缺失的订单，或仍需跟踪退出策略的已确认订单；`ENTRY_MODE=off` 也允许只读刷新旧订单。没有订单 ID 的 `unknown` 不猜成交、不重发，查询失败保留买单原状态，已确认买单不会因后续读取异常降级。`confirmed` 依据供应商确认，不是本地独立验证链上成交。

### 已配置的止盈止损

`EXIT_POLICY_PATH=config/exit-policy.json` 读取用户确认的规则；缺文件、错误格式或与授权参数不符时拒绝启动。比例采用 `hold_amount`，按触发时钱包的剩余持仓计算：

| 触发 | 操作 |
| --- | --- |
| 涨幅 +100%（入场价 2 倍） | 卖出当时持仓的 50%，以翻倍出本为目标 |
| 跌幅 60%（入场价 0.4 倍） | 卖出全部剩余持仓 |

没有其他买卖时，翻倍卖出 50% 后剩原始仓位的 50%；翻倍出本为未扣滑点、手续费的目标，不是净本金到账保证。`hold_amount` 包含该钱包后续增加的同币持仓。这是当前第三次通知实盘策略要求的两条 GMGN 固定退出规则。旧订单保留创建时的授权规则；下述动态保护仍是独立影子研究，不改变这两条实盘条件。

启用退出策略的 live 买单显式传 `condition_orders` 和 `sell_ratio_type`；网页/App 保存的预设没有公开的 API 自动继承保证。价格触发和卖出由 GMGN 服务端处理，本地每 30 秒轮转只读回查订单，独立价格监控继续运行。BSC 费用字段 `ENTRY_GAS_PRICE_BSC_WEI` 使用 wei（默认 `50000000` 即 0.05 gwei），SOL 的 `ENTRY_PRIORITY_FEE_SOLANA`、`ENTRY_TIP_FEE_SOLANA` 使用 SOL（各默认 `0.00001`）；Robinhood 不套用 BSC 费用参数，其条件单尚未实盘验证。`ENTRY_MODE=off` 只关闭研究开仓入口；第三次通知策略使用“停止计数”停止新买入，两者均不会撤销 GMGN 已接受的退出策略。

附挂是 best-effort，**买单成功不等于止损挂好**。开单明细独立保存策略 ID、授权规则、条件单状态和链上余额；查询 `GET /v1/exits` 可查看。SOL 第三次通知订单的回读核对钱包、完整 CA、计价币、买入金额与时间、两条条件，以及唯一策略身份；有买入交易哈希时核对哈希，否则明确标为金额与时间匹配，不能冒充链上归属证明。父单与子单状态符合要求时记录为 `observed`，表示供应商报告止损条件存在；`automaticTriggerVerified=false` 仍明确保留。缺页、冲突、模糊匹配或未知卖出状态都保持未核实，不自动补挂或重发买单。观察到平台条件不保证未来按触发价自动成交。

自动退出在已核实对应策略及全部子单终止、独立 RPC 确认买单及零余额后释放名额。TG 手动卖出提供 25%、50%、75%、100% 四档，点击后按最新链上持仓的最小单位整数计算，部分卖出向下取整，100% 使用全部余额；不二次确认，也不查询或等待撤销保护单。手动卖出经独立 RPC 核实成交和零余额后，单独保存清仓证据并释放名额，不依赖保护单的终止状态。买单 `confirmed`、原始成交证明及同一 CA 永不重复买入的记录保持不变；部分卖出、余额未知和 `paper_open` 继续占用名额。零余额不用于虚构卖出成交价或盈亏。部分止盈结果记录为 GMGN 的报告，实际余仓另用 RPC 查询。

历史联调记录（2026-10-09）：个人 Key 可读取三链绑定钱包，本地签名文件可成功查询 BSC/Solana/Robinhood 的 `STMix` 策略列表；当时三链 open 列表均为空。该次真实 BSC 报价在冷却后一次重试仍返回 `429 RATE_LIMIT_EXCEEDED`，未取得报价、未发送 swap。这是当日记录，不代表当前 SOL 第三次通知策略的运行状态。

### 动态止盈保护：前瞻影子验证

`EXIT_SHADOW_ENABLED=true` 开启独立持久化观察，页面新增“止盈保护”。它复用候选报价采样，不额外发起交易或行情请求；浏览器关闭不影响服务运行。每条链/CA 从启用后的首次新报价建立影子基准，不拿启用前的高点补造退出结果。V3/V4 **无固定持有时限，按行情持续保护**：持续上涨时继续跟踪，普通研究窗口截止不触发清仓；暂时缺价仅暂停新的价格判断，不生成时间退出意图。同币仍有影子余仓时继续同一条保护记录；重启恢复基准、保护线、已建议档位和余仓。影子全退后仍可保存新价格供比较，但不会再次建议全仓退出。

策略版本 `adaptive-shadow-v4` 是前向 treatment：翻倍前沿用 V3 的 -40% 影子硬止损、波动保护和动能判断；首次观察到 +100% 时卖出当时模拟余仓的 50%，以该时点重置独立 runner 峰值和保护线。runner 只有连续两个新鲜样本低于保护线才模拟清余仓；价格恢复或超过 5 分钟断档会重置连续计数。+500% 卖剩余 20%、+1000% 再卖剩余 10%。已经存在的 V3 记录继续按 V3 前向运行，旧记录和已冻结收益不重算。

V4 上线前使用 65 个有完整逐笔样本的已关闭影子窗口做同路径回放：全体胜率和中位收益与 V3 相同；63 个同池窗口的模拟毛收益总和由 +80.75% 变为 +91.62%，提升很小。包含跨池迁移样本时增幅明显更大，因此不能据此宣称可实现收益；V4 只用于收集前向证据，不改变实盘的 +100% 卖 50% / -60% 全部止损规则。波动窗口、数据缺口和迁移细节见 [价格观测与最终退出](docs/price-routing-and-final-exit.md)。这些是待验证的研究参数，不保证保本、盈利或按保护价成交。

钱包压力只使用报价时已经本地获取、最近 10 分钟内的同币逐笔买卖金额；公开来源或当前有效关联证据用于筛选钱包，交易哈希和事件索引用于去重，冲突及截断窗口不参与。供应商交易仍标为供应商报告，不能据此确认钱包归属。没有可靠证据时为“未知”，不把累计收益、持仓变化、AI 评分当作净流出。每次采样保留所用证据 ID、保护线、版本、间隔和触发原因。

接受的保护报价保存在 `EXIT_SHADOW_DATABASE_PATH`（默认 `data/exit-shadow.sqlite`），不使用扫描曲线的抽样压缩；代码默认容量 128 MiB，示例与当前生产配置上调为 1 GiB，最多 1000 个观察窗口。已经模拟关闭的未来比较样本最多每分钟一条，旧数据不删除。到达容量会停止相关写入、标记数据不完整并展示错误，保留旧记录；成功恢复后仍保留曾经缺失的标记。`EXIT_SHADOW_STALE_AFTER_SEC` 默认 180 秒，页面区分新鲜、过期和请求失败。采样来自独立多源现价路由，最多 30 秒有效；页面分别展示当前路由与模型最近采用的样本。网络与覆盖缺口仍可能错过瞬时价格，不能冒充真实连续成交。鉴权只读接口为 `GET /dashboard/api/protection` 和 `GET /dashboard/api/protection/:id`；详情返回最多 2000 条报价并注明响应是否截断，底层数据不因此删除。

止盈保护的收益按初始模拟本金加权：每次退出的收益贡献为“本次卖出的初始持仓比例 × 该次触发价格涨幅”；未退出部分另算浮动收益，两者相加为当前合计。全部模拟退出后冻结最终收益，后续代币继续涨跌只用于比较，不改写退出结果。已实现、浮动、合计和最终均为模拟毛收益百分比，不代表实际成交或账户余额，未计税费、滑点和 Gas；没有实际投入金额时不推算 BNB/SOL/ETH 盈利金额。缺少必要退出记录时显示无法核算；当前报价过期或不可用时保留已实现部分，浮动和合计显示未知。

研究筛选的 live 入口保留内部退出能力证明要求，缺少证明时返回 `ENTRY_UNATTENDED_PROTECTION_UNVERIFIED`。本人启动的 SOL 第三次通知策略是独立入口，按明确配置发送买单和两条 GMGN 条件单，并持续回读实际状态；不会把影子模型结果当作实盘保护。`/health` 分别展示 `configuredEntryMode`、`configuredThirdSignalMode`、`countingRunning` 和 `executionEnabled`。`executionReady` 只表示本地配置满足入口要求，`unattendedProtectionReady=false` 表示尚不能宣称未来自动保护成交已获验证；它不代表第三次通知实盘策略被关闭。代码与模拟响应测试不等于真实买入、卖出或止盈止损触发已验证。

## HTTP、查询与保留期限

除 `GET /health` 外要求 `Authorization: Bearer <INGEST_TOKEN>`。导入使用 `Content-Type: application/json`，最大 64 KiB。远程部署需提供 HTTPS 和访问控制。

| 接口 | 用途 |
| --- | --- |
| `GET /v1/exits` | 已配置的退出规则和订单退出状态；需认证，只读 |
| `GET /v1/status` | 配置预检，不联网 |
| `GET /v1/scanner` / `POST /v1/scanner/run` | 扫描状态诊断 / 手动执行一轮 |
| `POST /v1/signals` | 标准信号 |
| `POST /v1/notifications` | 通知原文包装 |
| `POST /v1/debot/stories` | DeBot 原响应包装 |
| `GET /v1/signals` / `GET /v1/signals/:id` | 缓存中的最近事件 / 单个事件及报告 |
| `GET /v1/signals/:id/report` | 中文文本报告 |
| `GET /v1/signals/:id/history` / `GET /v1/signals/:id/imports` | 缓存中的历次评估 / 人工导入原文 |
| `POST /v1/signals/:id/retry` | 保留原事件时间重新研究，适用当前开单策略 |
| `GET /v1/orders` / `GET /v1/orders/:id` | 持久订单明细 |
| `POST /v1/orders/:id/reconcile` | 查询既有订单，不重新提交 |

```bash
# report/retry 依赖运行中的服务，只能访问其仍在缓存的 ID
npm run report -- <报告ID>
npm run report -- <报告ID> --json
npm run report -- <报告ID> --history
npm run retry -- <报告ID> --text

# orders 直接读账本，不要求服务运行
npm run orders
npm run orders -- <订单ID>
```

**开单明细保存在 `data/orders.sqlite`，启用控制台或自动复评时另存有上限的扫描摘要及复评队列 `data/scans.sqlite`；启用长期钱包研究时另存 `data/wallet-history.sqlite`。** 正常运行要求磁盘订单路径，拒绝空值、`:memory:` 和 `file:` URI。信号原文、供应商原始响应、原帖、钱包原始响应、完整报告/历史用内存数据库，默认按 30 分钟 TTL、200 个事件清理；在途研究暂保留，重启清空。用于网页展示的叙事文本（最多 12,000 字符）、社交参考、限时复评所需的最小信号，以及规范化钱包证据已另行持久归档，不受这项内存 TTL 影响。订单保存地址、金额、报价、状态、交易信息和有限入场摘要/证据链接，不复制整份研究。精简扫描归档的保留策略见 Web 控制台章节。

缓存内同来源/事件 ID 幂等，内容冲突拒绝；处理租约 5 分钟，新任务取得租约后旧任务不能覆盖。候选默认有效 60 秒，过期读取降为观察；重试不刷新原事件时间。订单幂等跨重启保留。

旧版 `data/` 研究库或其他文件**不会自动删除或迁移成订单**，当前运行时不再写旧研究库。手工输入文件、终端重定向输出由维护者管理，不在缓存清理范围内。

旧版近门槛对照按“一组资金支持／画像待补／其他资金支持缺口”各最多同时观察 2 个，保留 30 天／1,000 币。2026-10-15 起运行时改为以下更广的持续复盘登记；旧对照完成原观察窗口，原始数据和系统页统计仍保留。

### 持续复盘与前瞻验证

服务运行时自动为新完成的 live 分析按 **chain＋CA** 建立复盘档案。首次结论、策略版本、原因、检查结果、资金组、净买入、前置钱包／公开进场线索和社交链接在登记时冻结；后续复评或事后上涨不能改写这些因子。重复信号不算新的独立样本，名称缺失可由后续同币报告补全。历史扫描不会被伪装为新模块当时已经记录的样本。

候选沿用现有追踪；WATCH、REJECT 各最多同时抽样 3 币，按到达顺序选入。未分到额度的币保留首次判断并明确标为容量未采样，不用后来涨幅重新挑选。沿用独立多源现价路由与每轮最多 30 个目标额度；保护仓位优先并为普通候选/对照保留轮转名额，GMGN 每轮最多一个回退请求；支持的池复用原链上订阅容量。限流、断连和不支持的池会造成覆盖缺口，不承诺每币每分钟必有报价。

复盘价格基准是**登记之后首次获得的有效报价**，与“条件后追踪”的候选基准相互独立。记录登记后 1／6／24 小时的首个报价，最多容许迟到 10 分钟；基准迟到超过 10 分钟则固定窗口保持缺失。保留采样高点、当前涨幅、峰后最大回撤、最大采样间隔，以及首次观测到 +50%、+100%、回撤 30% 的时间。突破时间是采样确认时间，不声称恰好是市场穿越阈值的时刻。最高采样涨幅不作为固定窗口收益或成交利润。

行情采样同时复用 GMGN `token info` 的流动性、持币地址数和前十持仓比例（[官方字段定义](https://github.com/GMGNAI/gmgn-skills/blob/main/skills/gmgn-token/SKILL.md)），没有字段就保持未知。钱包证据只读长期本地库：每次样本查最多最近 10 分钟、且不早于登记的已观测买卖，交易时间与本地发现时间均须不晚于该次报价。去重多来源，排除冲突、索引歧义和缺失金额；超出 500 条读取上限时净额保持未知。时间线保留有界交易例证及来源，可核对交易；它不是全币完整资金流，也不证明钱包归属或拉盘原因。

“持续复盘”页面展示采样覆盖、首次判断、固定时点结果和证据时间线。后台每 60 秒更新并保存精简研究汇总，关闭页面仍持续积累与复盘。按链、首次结论、策略版本分组，对比首次冻结因子的有／无／未知样本；按登记时间先 70% 后 30% 分成发现和后期验证，并报告未覆盖数量。早期样本的整个结果窗口必须在后期登记分界之前完成，跨界样本剔除并单列。每种因子的有／无组在两个时期都至少取得 20 个有效结果后，才标注方向是否重复；这仍是观察相关性，不是统计显著性、独立外样本检验或预测胜率，不自动改交易策略。

新复盘记录独立于短期扫描清理，保留最多 90 天／20,000 币，容量清理优先移除未采样记录。每币最多 256 个价格点、32 个时间线节点；保留基准、采样峰值及关键里程碑，普通节点会稀疏化。钱包原始长期库的保留规则不变。接口 `GET /dashboard/api/followup` 返回汇总；`/followup/records`、`/followup/groups`、`/followup/learning` 分页返回列表；`/followup/:chain/:address` 返回单币完整证据。以上使用现有工作台认证且只读。该模块不产生订单，也不调整开仓模式或安全门槛。

## 链上长连接与 GMGN 降频

`CHAIN_STREAM_ENABLED=true` 启用只读监控，不改变 `ENTRY_MODE`。GMGN 继续负责发现、标签、合约安全素材、有限历史研究及已有订单接口；没有调用其未公开的 WebSocket 协议，也不依赖浏览器 Cookie。BSC、Solana、Robinhood 各使用一条公共 RPC WSS，独立 HTTP 用于校验、当前状态读取和断线补数。模板提供 PublicNode 三链 WSS、Solana PublicNode HTTP；BSC HTTP 使用 bloXroute，Robinhood HTTP 使用官方 RPC，两种传输各自核验链 ID（PublicNode HTTP 要求日志查询指定合约，不适合跨币钱包补数）。无需新 API Key，公共服务也有配额和可用性限制。

- 动态目标：每链最多 10 个钱包、8 个池，可由 `CHAIN_STREAM_MAX_WALLETS` / `CHAIN_STREAM_MAX_POOLS` 调整。钱包优先取已积累的有效关联候选及其带单钱包，空位取近期观测的钱包。这些关系仍是待验证线索。代币来自最近 24 小时已符合研究条件的候选，超出订阅额度继续用 GMGN。浏览器刷新不会新增 RPC 订阅。
- BSC 验证 Pancake V2/V3 的工厂、实际配对、完整 CA、精度和当前区块；Solana 验证 canonical PumpSwap 毕业池的程序、PDA、Mint 与 vault，处理官方虚拟报价储备。内盘、其他 AMM 和 Robinhood 池暂未实现价格解码，会明确回退，不能把节点连接成功当作代币价格已有覆盖。
- 池事件使价格待刷新，合并高频事件并限制每轮读取数量，安静时也定期重读。USD 参照来自 Dexscreener 中完整资产匹配的报价，缓存不刷新其取得时间，超过 120 秒拒绝；USDT/USDC 也不写死为 1 美元。报价是费用、滑点之前的现货估计，不是可成交价格。扫描摘要和影子保护报价保存链上池、协议、报价币、USD 参照时间、区块/槽和来源（EVM 为 RPC 当前观测，Solana 池读取为 confirmed，并非 finalized）。
- 只有当前连接、有效订阅和新鲜链上价格都正常，才跳过该币的 GMGN 价格请求。断线、旧报价、解码失败或 USD 参照失败恢复 GMGN 回退；GMGN 自己限流时仍可能有报价缺口，不伪装为连续实时止损。切换来源不重置已有候选基准。
- BSC/Robinhood 定向订阅 ERC-20 Transfer 日志，保存完整 tx、log index、区块 hash、原子数量和重组撤回状态。它们是 RPC 观测日志，未声称最终不可逆，也不等同于买卖或资金控制关系。本版不遍历所有区块交易、不覆盖 EVM 原生币和内部 trace 转账。
- Solana 订阅目标钱包 mentions（每订阅一个钱包），以已核验主网 HTTP 的 finalized 签名页确认实际参与事实；不把仅由 WSS 声称的签名提升为确认事实。Solana HTTP 与 WSS 配置需同主机；界面明确显示配对 HTTP 核验，不声称 Solana WSS 支持独立 genesis 查询。只涉及 ATA 而未提及钱包地址的交易可能遗漏，也不会从签名直接推断买卖方向。
- 心跳、指数退避和订阅恢复由本地传输层处理。补数使用独立钱包游标、去重 ID 和有限窗口；失败保留完成游标；Solana 每轮最多 3 页，每个成功满页保存分页进度，后续轮次和重启接着补，整段完成后才推进完成游标；无法完成的范围保持待补，异常截断明确显示缺口。首次启动只采有限近期活动，不宣称取得全部历史；仅补钱包活动，绝不把停机期间历史价格补成当时已观测的高点或止盈信号。

链上事实单独持久保存在 `CHAIN_STREAM_DATABASE_PATH`（默认 `data/chain-stream.sqlite`），默认上限 256 MiB。达到上限停止相关写入并标记不完整，保留旧事实；不偷偷删除关联研究数据。它与 GMGN 钱包研究库独立，不会把转账偷换成 GMGN 买卖记录或直接输入关联卖压模型。当前页面在“运行状态”显示连接、订阅/覆盖、补数、容量和近期原始链上事实，鉴权只读接口为 `GET /dashboard/api/chain-stream`。三链节点状态正常不代表所有钱包、所有协议或所有历史均已覆盖。

## 每日信号复盘

JEV 并行研究在独立栏目展示，按当时可知的数据冻结原策略与模型结果，再追踪后续价格。额度不足、认证失败、限流、超时和异常响应均降级为“不可用”，不改变原有买入、安全或退出规则；本地调用预算与恢复时间可在栏目查看。配置、比较口径和限制见 [JEV 并行对照](docs/jev-shadow.md)。

`meme-daily-review.timer` 每天北京时间 09:00 运行独立任务，服务器重启后补跑。每次为前一自然日生成报告，并为前两天保留新的复盘修订，补齐较晚取得的后续证据。工作台“每日复盘”独立加载、每页 20 条；日期与报告 ID 固定分页视图。任务失败时保留已有报告，展示错误标记。

复盘分母是本机实际留存的全部通知，按链与完整 CA 去重。通过 DeBot/Ave 通知的供应商回溯涨幅，以及独立行情库的同池本地采样寻找大涨案例；两种涨幅分列，标明各自起点、采样延迟和缺口。平台倍率不擅自换算成投资回报，缺价不计零，历史未保留的榜单字段不补造。首次冻结判断、后续可用判断和对应 report ID 的执行审计分别保留；当前 ENTRY_MODE=off 不能代替过去的执行记录。新增审计只记录判断 ID、链/CA、结果/原因与时间，不保存原始报告或凭据。

每日任务从覆盖缺口自动生成 review-coverage-v1 前向研究采样计划：一半名额公平轮转，另一半补充覆盖不足的链与来源，总请求预算不变；计划只在生效后影响采样，48 小时未续更或读取异常自动回退。读取分母不完整时不发布计划。计划与实际选入原因独立留痕；它不会修改开单、安全、仓位或止盈规则，亦不表示已验证盈利。

重点案例采用本地或平台已知涨幅 ≥100%，以及 Ave 原样展示倍率 ≥2x 两种入口；百分点与倍率分组显示，不互相换算。发行阶段/交易路径尚未支持、分析超时、钱包证据不足分别归因。源通知和扫描库清理时在同一事务记录删除水位；修剪涉及报告区间时标记覆盖不完整。任务复用已有 Ave 登录态且只读，续期由主服务负责，避免两个进程互相覆盖会话。

运行 `npm run daily-review`；`-- --date YYYY-MM-DD` 可补指定日期，`-- --offline` 只用留存数据。独立报告/执行审计库跟随扫描库路径追加 `.daily-review.sqlite`，研究计划追加 `.review-sampling.json`。报告最多保留 90 天或合计 50,000 条代币明细，达到容量时整份移除最旧报告；执行审计保留 90 天，供应商统计快照保留 30 天，长期钱包库不受影响。同一报告日期在同一执行自然日仅发布一次。任务逐行读取大表，独立进程有 CPU/内存预算；异常退出由 systemd 补记失败状态。部署文件见 `deploy/meme-daily-review.service` 与 `deploy/meme-daily-review.timer`，启用前先构建。

### 退出质量与前瞻学习覆盖

每日 09:00 的独立复盘任务另保存最近 7 日已清仓影子仓的退出质量快照，按上海自然日幂等、保留 90 天。该快照与信号日报日期独立，HTTP 页面只读已发布结果；普通保护列表不增加逐仓历史扫描。审计失败会保留旧快照、显示单独错误并继续信号日报，任务以部分失败退出。

- 最终收益采用分批退出对初始本金的贡献；权益峰值为已实现收益加剩余仓位浮盈，不能用全币峰值直接减最终收益。
- 清仓后 5 / 15 / 60 分钟只接受目标时点后 2 分钟内首个同来源、同池报价。比较的是最后卖出部分若继续持有，对初始本金收益造成的差值，不选择窗口最高价。
- 缺价、未到期、未知池、池或来源不符、容量截断分别计数，不补成零。旧样本没有池依据时保持未知。单仓最多读取 2000 个退出前样本，日报最多 1000 仓、展示 10 个案例。
- 均值是每仓等权模拟毛收益，不含滑点费用，不是账户收益。按清仓时策略版本分组，迁移仓可能经过旧规则，不能当成完整版本的回测。此模块只观察，不改变保护参数、发出买卖单或开启实盘。

持续跟踪对主动队列之外的已登记对象，复用 meme 模块已经取得并保存的新鲜同池行情；不补历史、不重写首次判断，也不增加外部请求预算。主动调度数量、被动复用覆盖、总观测量和缺失量分别展示。迟到基准仍不能参与固定时窗结果；被动样本有机会性覆盖偏差，不能视为随机抽样。新增回调与订单、保护仓和候选筛选隔离，失败单独记录在 meme 状态中。

研究顺序：先补覆盖，再以触发当时可知的特征比较成功与失败对象，最后用时间上后到的独立样本验证。重点验证热度加速、独立买家承接、已核验名人原帖、前置钱包到公开钱包的后续接力，以及卖压和流动性衰退；这些是待验证假设，不能从事后涨幅直接推成新买入规则。每项改动应保留原策略对照及缺失分母，成本与成交质量另行验证后再决定是否应用。

### 钱包直听与 100ms 快速预判

`WALLET_FAST_ENABLED=true` 在独立 Worker 中复用链上 RPC 端点监听钱包，要求 `CHAIN_STREAM_ENABLED` 与钱包历史采集已启用。每链沿用 `CHAIN_STREAM_MAX_WALLETS`（当前 10，最多 30）；优先从已有后续验证、重复提前、公开 KOL 来源组取得新鲜画像，其余名额由既有关系目标填充。这些分组不证明钱包归属或未来盈利。

`SOLANA_WALLET_WATCHLIST` 可配置逗号分隔的完整 Solana 钱包地址，最多 5 个，修改后重启服务生效。这些固定目标同时加入快速监听和确认后历史采集，不随自动名单轮换；在自动名额之外预留订阅位置，自动名额加固定目标不得超过 30。例如自动名额为 10、固定目标为 1 时，最多监听 11 个不同钱包。重复地址只订阅一次，固定目标不会获得额外的聪明钱标签、身份确认或交易权限。节点接受订阅和后续消息到达情况应通过系统页的订阅状态核验；固定名单本身不保证同区块成交。

Solana 使用 `logsSubscribe / processed`；BSC 与 Robinhood 使用已入块 ERC20 转账日志。原来的确认后历史采集继续运行。监听线程先核验链身份，内存画像与风险缓存每 30 秒刷新、120 秒失效；监听名单每 5 分钟重新选取，避免画像重算引起订阅频繁更换，期间空位可补入新目标。快速路径只做消息校验、完整地址匹配、去重、钱包分组和已缓存的来源/合约安全结论检查，不访问 SQLite、GMGN 或模型。转账、钱包提及和 `processed` 预警都不标记为已验证买入。

100ms 的计时起点是 **WebSocket message 回调入口、JSON 解析之前**，终点是快速预判完成；这不测量节点到服务器传输、内核/事件循环调度前的等待，也不包括详情补查、完整风控、报价或成交。页面展示累计样本、最近 2048 个消息的 P50/P95/P99、启动后最大值与超时数，并独立展示事件循环延迟、送达主线程的耗时、丢弃数。未收到实际样本时保持未知；基准测试与线上数字不能相互代替。

预判后异步进行链上交易分类，独立查询 RPC，不再用 GMGN 的 `buy` 标签代替核验。核验队列最多 64 笔、单钱包最多 4 笔、每分钟最多开始 60 笔；同笔多条代币日志合并核验完整回执，避免把报价币的一条转账当成整个交易。单次核验最多 20 次 RPC 请求、总等待预算 12 秒（包含节点退避等待），节点未返回确认回执最多尝试 3 次，120 秒后失效。完整研究另有最多 16 笔队列，每分钟最多 6 笔；GMGN 限流或研究繁忙不会暂停链上分类。超限、过期和丢弃数量均独立展示。

分类包括已核验买入/卖出、他人代付买入、批量派发线索、转账、自身账户转移/零变化、授权、加减流动性、原生币包裹/解包、失败、撤回和未知。只有支持的协议操作与观察钱包的资产流向一致时才记买卖。Solana 使用 confirmed 交易的实际指令、签名者、账户所有者、原子余额差和对应调用内部的代币转移；手续费与已识别代币账户租金不作为买入支出。当前支持 Pump、PumpSwap、Raydium LaunchLab 的指定买卖指令，包括可核验的内层调用。LaunchLab 程序身份不证明它就是 Bonk 的特定平台，发行平台仍由原来的来源检查负责。

EVM 核对交易、成功回执与当前规范区块的身份；Four / Flap 使用官方发出地址、成交事件中的参与钱包和代币流向，Pancake V2/V3 另外向官方 factory 核对池成员关系，并将池成交数量与钱包的两条资金流对应。V2 买入可识别池输出中明确转给代币合约自身或销毁地址的扣款：池总出币须与成交数量一致，钱包按净到账计数；这不证明税率或合约安全。V3 使用 Pancake 实际包含协议费用的事件定义；普通 Uniswap 事件签名不能替代。仅有 Swap/Transfer 的事件签名、与名人钱包相关或供应商 buy 标签均不能通过。EVM 的流向来自回执日志，不是逐交易状态差分，恶意代币、未知协议、复杂路由、转账税导致的数量歧义、代付、内部原生币收款等证据不完整时不猜成交方向；安全筛选仍独立运行。批量派发是日志线索，不保证代币实际有价值。单纯收到别人支付对价买来的代币不能计为自己的主动进场；保留发起钱包以供关系研究，不推断同一控制人。

分类证据存入 `WALLET_ACTIVITY_DATABASE_PATH`，默认 `data/wallet-activity.sqlite`，上限由 `WALLET_ACTIVITY_MAX_MB` 控制（默认 128 MiB）。只保留身份、分类理由、原子数量和必要转账方向，近期面板最多展示 20 条。达到容量上限明确报错，不能保存证据的买入不进入研究。此通道只有已核验买卖进入钱包交易历史；其它分类独立保留，不能增加买入或盈利计数。撤回会给分类档案写不可复活的标记并取消未执行的分析，不删除已留存的历史研究；最终一致性与归属结论需继续复核。此来源继续标记 `source=wallet` 并在开仓入口保持研究模式，未启用实盘。

监听通知最多保留 64 个待主线程接收的批次，超量显式计为丢弃；断线缺失由既有历史观察处理，快速通道不回放旧事件触发新单。近期预判仅保留本次服务的最新 100 条（页面最多 20 条），完整筛选结果和核验到的钱包交易沿用原持久档案。

运行 `node --import tsx scripts/wallet-fast-benchmark.ts` 可执行不联网、不交易的三链各 10000 条消息重放；独立 Worker 测试另检查主线程阻塞时的隔离效果。

运行 `node --env-file=.env --import tsx scripts/wallet-activity-replay.ts --limit=20` 可对既有链上档案进行有上限的历史分类回放。只保存分类，不发送筛选信号、不写买入计数、不下单。回放结果不代表实时分类延迟。

分类协议依据（2026-10-21 核对）：[Solana getTransaction](https://solana.com/docs/rpc/http/gettransaction)、[Pump/PumpSwap IDL](https://github.com/pump-fun/pump-public-docs/tree/639b87fb45c3adeffa6f7c4a1bf0cb85e392bf22/idl)、[Raydium LaunchLab IDL](https://github.com/raydium-io/raydium-idl/blob/e7e0c96fe77bcf6a020b84a44c47a722aac8e359/raydium_launchpad/raydium_launchpad.json)、[Four TokenManager2 ABI](https://github.com/four-meme-community/fourmeme-docs/blob/5f7f589b042e4e3b41c2c214d0fe3a81b36725a9/abi/TokenManager2.lite.json)、[Flap IPortal](https://github.com/flap-sh/FlapVaultExample/blob/5949cc7eb99bcb5ac5f679cc710ae456e627f12a/src/flap/IPortal.sol)。协议升级和未覆盖操作保留为未知，不自动学习新事件签名为可信。

### Solana 原生交易与 Jito 防夹

`SOLANA_EXECUTION_PROVIDER=pump_native` 将第三次信号开仓接到官方 Pump / PumpSwap SDK，当前限定 SOL 计价、已核验的官方曲线与 canonical PumpSwap 池。普通和既有 cashback 币均按对应指令构造；未覆盖的池型、报价币、Token-2022 扩展或超出 v0 长度的交易明确拒绝，绝不回退 GMGN 下单。GMGN 仅继续提供开仓前 Top10 / 捆绑 / 老鼠仓数据。

原生签名文件由 `SOLANA_NATIVE_KEYPAIR_FILE` 指定，必须是当前 `ENTRY_WALLET_SOLANA` 对应的 64 字节 JSON keypair，所属用户一致、权限 600；模板中的相对路径按项目工作目录解析，服务部署建议改为绝对路径。不要填 GMGN API 密钥。`SOLANA_NATIVE_RPC_URL` / `SOLANA_NATIVE_WS_URL` 可覆盖现有链上端点；Jito 默认官方主网入口，tip / priority fee 分别受配置上限限制。签名器、主网身份或长连接未就绪时，第三次信号入口保持不可执行。

每笔交易先通过未签名预演，签名后的交易只发送到 Jito `bundleOnly=true`，同笔交易包含 tip 和只读 `jitodontfront` 标记。公共 RPC 不接收可广播的签名交易；通道异常不公开广播。此机制降低被夹风险，不是零 MEV 或成交价格保证。官方说明：[Jito 发送与 Sandwich Mitigation](https://docs.jito.wtf/lowlatencytxnsend/)。

本地 SQLite 在广播前保存签名、完整交易、有效高度和业务标识。提交超时保持未知；未过期仅重播相同签名。买入广播尝试永久占用 CA，不自动重买。手动卖出和自动退出共用钱包 / mint 的唯一未决锁，重启按签名恢复。交易读取兼容 v1，本版构造 v0；SDK 指令版本与交易版本分别处理。

持仓通过独立 WebSocket 接收 confirmed 曲线、池子、余额账户及钱包 Token / Token-2022 账户数据，用官方 SDK 公式在本地计算实际持仓数量的卖出报价。正常价格检查不发 HTTP；每个持仓由账户变化单独触发，不等待轮询周期，也不等待其他币的卖出结果。PumpSwap 等待池子及两个金库的完整更新，不能把半组账户拼成新报价。静默池保留真实的最后市场更新时间，不把本地检查时间冒充成交时间。HTTP 用于初始化、断线或缺帧后的限频恢复、余额归零复核及实际交易前校验；`SOLANA_NATIVE_INVENTORY_RPC_URL` 单独指定支持钱包账户索引的 RPC。迁移到 PumpSwap 会切换订阅。

行情热路径按变化账户增量解码，复用已核验的固定地址和未变化参数。普通行情、dirty 标记及检查快照在内存中更新，约每秒合并落盘；止盈止损每次完整报价仍立即判断，首次有效报价、余额造成的成本变化、退出意图、成交与关闭继续可靠事务保存。涨跌越档单独捕获并持久排队，不因快照合并丢掉短暂峰值。重启作废旧报价，等待新鲜状态。确认全仓余额归零后释放该币订阅、报价缓存、库存和预热任务结果；共用账户保留给其他持仓。已关闭仓位从活动集合移除，迟到帧及旧异步结果不能恢复监控；永久开仓记录仍保留，部分卖出继续监控余仓。

买单广播前必须确认目标池及余额账户的订阅已经就绪，避免买入后才发现无法监听。账户订阅必须逐个得到确认，且持续收到推进的链上头消息；未确认的订阅最多补试两次，仍失败则保留失败状态。新币等待订阅时不暂停其他已有完整订阅的持仓。头消息超过 1.5 秒没有推进即使连接未关闭也判为不可用，作废本地快照并阻止新开仓，这个阈值是故障检测门槛，不是价格轮询间隔。链上 confirmed 成交可先启动保护，finalized 才确认最终订单；外部清空先暂停涨跌提醒，聚合最终余额归零才正式关闭。固定策略仍为上涨 100% 卖剩余 50%，下跌 60% 卖全部；广播前再次核对最新余额和报价条件。TG 四档卖出、成交通知、涨幅档位及最终兑换盈亏使用同一持仓账本，外部转账不会伪装为卖出收益。

原生持仓和签名执行运行在独立子进程，扫描或网页主线程阻塞不会阻止该进程处理价格。单实例内核锁防止重复执行；共享开单账本争锁时快速退出写入并排队重试，既有持仓的价格判断及独立通知队列继续运行，同时阻止新开仓。通知通过持久队列交给主进程，主线程阻塞期间通知可能延迟，保护不等待通知。子进程崩溃会重启并恢复持仓和未决交易；整个服务停机期间仍无法卖出。`SOLANA_NATIVE_JOURNAL_PATH` / `SOLANA_NATIVE_POSITIONS_PATH` 及其旁边 actions、process 数据库必须持久保存，不能清除历史来重开同一个 CA。状态分别展示链上头龄、订阅确认和账户消息接收至本地评估耗时；后者不包含链上事件到节点推送的延迟、交易构造、广播或确认。公共 RPC 没有可依赖的生产 SLA，不能据此承诺全程 100ms。
