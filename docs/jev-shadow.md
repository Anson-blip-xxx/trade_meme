# JEV 并行对照

JEV 是可选的异步研究观察器。完成一次真实数据筛选后，先保存原有判断，再在后台向共享官方 SDK 请求辅助评分。它没有订单适配器、签名能力或修改策略的权限，既不能放行原策略拒绝的代币，也不会因为模型不可用阻止原策略。`ENTRY_MODE` 与 JEV 开关完全独立。

## 输入与评分

输入冻结在报告的 `evaluatedAt`，只纳入该时点已经取得的新鲜行情、已观察的钱包交易及可核对时间的社交证据。未来价格、事后峰值、原策略总分和决策不发送给模型。代币及钱包使用临时别名，保留来源、时间和证据摘要；供应商标签不提升为链上核验或钱包归属证明。叙事原文目前不进入模型，因此不能把这版评分理解为完整的叙事语义分析。

模型固定 `jev-1.13.0`，规则版本 `meme-shadow-v1`。维度为热度、交易情绪、钱包接力、传播线索与名人关联；缺失维度为 `null`。总体 0–100 分是研究优先级，不是胜率。供应商“买入”与本地链上已核验交易分别标注；名人主页链接不作为背书，提到 CA 也不等于支持项目。完整 CA、原策略与模型结果只在本地记录中用于关联。

## 降级与预算

- 单次总期限默认 2 秒，无 SDK 自动重试；队列有上限和过期时间，单并发，不进入钱包 100ms 快速预判路径。
- 额度不足或认证错误进入冷却；429 尊重有界 `Retry-After`；超时、网络和服务故障退避。冷却后只允许单个请求探测，成功后恢复。拒绝服务、未安装 SDK、无密钥、响应格式不合规以及存储故障均保留原策略。
- 不可用结果的分数为 `null`，记录安全原因码和可恢复时间；不把失败当作 0 分，也不复用旧分数冒充当前结果。错误正文与密钥不写入界面或数据库。
- 默认本地日上限为 500 次调用、1,000,000 tokens，按北京时间自然日统计并持久化，重启不会清空预算。发请求前预留保守额度；未返回用量的超时或异常仍占预留额度。界面区分已报告用量与未知用量预留。这不是供应商剩余额度查询，也不涵盖其它项目使用同一密钥产生的费用。
- 数据独立保存到 `data/jev-shadow.sqlite`，默认上限 128 MiB。存储路径冲突只禁用 JEV，不碰订单或会话库。

配置项见 `.env.example` 的 `JEV_*`。共享 SDK 默认位于 `/home/ubuntu/shared/jev/node/index.mjs`，从已有本机共享配置读取密钥；不需要把密钥复制到前端或仓库。默认关闭，部署时显式打开 `JEV_SHADOW_ENABLED=true`。

## 前向比较

每条记录保留模型输入摘要哈希、判断时间、完成时间、原策略、模型版本和状态。只以模型完成后两分钟内首个新报价作为共同起点，避免把模型响应前的涨幅算成可捕捉收益。后续 5、15、60 分钟使用目标时点后有限窗口内的首次报价，并展示采样最大涨幅和回撤；不选择区间最高价替代固定时点结果。

原策略通过硬性检查并给出 `BUY_CANDIDATE` 的记录才进入可比候选集；JEV 对照组只从这些候选中选择 `support`。原策略 WATCH / REJECT 的有效评分也保留后续价格观察，供复盘漏选线索，但不混入可买候选对照或获得交易权限。缺失、模型不可用及不合格记录单独统计，不算零收益。重复评分是重复的决策观察，可能属于同一代币，不能当作独立交易或等权账户组合。比较有行情覆盖与信号选择偏差，需积累后续样本再评估。

页面展示的是 **报价采样毛涨跌幅**，没有真实成交、滑点、费用、资金分配与退出路径，不能称为净收益或模型盈利提升。现有止盈保护模拟及最终收益继续保留在原栏目；此模块不会改动它们，也不会自动训练或发布新的开仓策略。
