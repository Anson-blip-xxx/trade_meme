# Telegram 私聊交易通知

在服务器 `.env` 设置 `TELEGRAM_BOT_TOKEN` 和数字形式的 `TELEGRAM_CHAT_ID`。先用目标 Telegram 账号向自己的机器人发送 `/start`，再重启服务。凭据只存本地，不能提交 Git 或发到聊天。`TELEGRAM_ENABLED=false` 可以关闭发送；未配置凭据时显示“等待配置”，不会调用 Telegram。

首次连接会发送一条明确标为连接测试的消息，注明当前开仓模式。通知、持仓查询与状态查询本身不提交交易；本人点击“启动计数”后启动配置好的第三次通知实盘策略，达标后自动提交买单及配置的止盈止损。本人点击持仓旁的卖出比例按钮，直接发起该比例的卖出，不再弹出二次确认。

持久键盘增加“持仓查询”，也支持 `/positions`、`/positions 2`。每页 5 个系统已登记的实盘持仓，展示链、名称、完整 CA、数量、参考价格、涨幅基准、报价时间和保护状态，可翻页与刷新。查询使用监控缓存，过期报价明确标注，未知数量不显示成零。新信号的处理链由 `SCANNER_CHAINS` 控制；当前部署仅 `solana`，已存在的其他链持仓保护不随新信号停用而关闭。

私聊直接发送完整 Solana CA，或发送 `/token <CA>`、`/contract <CA>`，返回 GMGN 合约详情卡。卡片包含名称、RPC 查询的 SOL 余额、价格、按流通量估算的市值、池子两侧储备、持有人数、内盘进度、权限、Top10、排除池子/销毁地址后的 Top5，以及明确标为交易量口径的捆绑和老鼠仓占比。GMGN 某个接口失败时只把相应字段标为未知，仍保留 CA、余额及固定域名的浏览链接；“刷新”会绕过 10 秒短缓存。GMGN 顶层与统计区的动态持有人数短暂不一致时，仅将持有人数标为未知，不影响其余详情。发送 CA 和刷新只查询详情；只有本人点击卡片上的金额按钮才会提交手动买入。金额区按两行显示 `0.1 / 0.5 / 1 SOL`、`3 / 5 SOL / 自定义`。

预设金额点击后立即执行，不再二次确认，也不使用自动信号的市值、Top10、捆绑钱包、老鼠仓等项目风控；GMGN 详情缺字段不会隐藏按钮或阻止这次本人操作。“自定义”会建立 5 分钟的单次输入状态，随后直接发送最多 9 位小数的 SOL 数量即执行，非法或过期输入不会下单。卡片买入仍执行交易必需的 CA、签名器、RPC/Jito、余额、持仓额度、幂等及永久禁止同 CA 重复开仓校验，并附加当前止盈止损保护。独立的 `/native_buy <CA>` 确认入口继续固定 0.01 SOL 并保留原有 GMGN 持仓风险检查。第三次信号的自动买入路径仍完整执行市值、时效、Top10、捆绑钱包、老鼠仓等自动风控。

Solana 每笔持仓下方提供 **25%、50%、75%、100%** 四档卖出按钮。点击时读取最新链上余额，以原子单位的整数计算 `余额 × 比例 ÷ 100`，向下取整，避免浮点精度损失；100% 直接使用全部原子数量，不遗留计算造成的尾数。数量不足一个最小单位时说明原因，不发送零数量卖单。报价期间余额变化则重新取余额和报价，不能使用旧持仓数量超卖。

卖出请求直接调用 GMGN swap，使用配置的滑点，不查询、撤销或等待保护单；平台保护单的后续状态由持仓监控独立观察。成交以 GMGN 回执和 finalized 链上交易核验，部分卖出通知实际成交量与剩余数量；全仓完成还需链上余额为零，未完成核验时显示“待确认”，不把提交当成成交。

每笔请求显示代币、卖出比例及请求编号，区分正在提交、已提交待核验和已成交。提交后的 RPC 或回执查询异常只显示“仍在核验”，不会说成未提交或卖出失败。持仓查询会显示正在核验的比例，并暂时隐藏该币的四档卖出按钮；余额已为零但本笔尚待核验时仍显示进度。旧按钮被再次点击时会明确回复上一笔的比例及“本次未提交”，不会把第二次点击当成第一笔的失败。后台结果附带查看最新持仓和卖出状态的按钮，核验完成后恢复剩余持仓的四档操作。

手动操作只接受配置的本人私聊。同一行四个按钮共享一个不含地址或凭据的单次操作标识：选定任意比例后，重复点击这一行只返回该请求的状态，不会再次卖出；需要继续减仓时刷新持仓，使用新按钮。同一持仓已有卖单处理中时也不再提交另一笔。重启恢复只查询已提交订单，未知提交不会自动重发，未提交的中断请求须刷新后重新点击。旧版预览／确认按钮只提示刷新，不再撤单或卖出。手动卖出独立于计数启停，卖出不会清除永久禁止再次开仓的记录。

持仓和状态的只读按钮不会因为原消息超过两分钟而失效。点击后先确认已收到操作，再通过持久消息队列回复处理结果；状态查询不能变成策略启动。

每单金额配置为对应链原生币总余额的 **3%**（`ENTRY_BALANCE_BPS_*=300`），不是持有 Meme 的市值；金额再受手续费预留和待结算资金占用约束。当前仅处理 SOL。本人点击“启动计数”后，DeBot 与 Ave 分开累计新通知；同一来源第三次通知市值不超过 10 万美元，且通过开仓核验时自动提交实盘买单。每次新通知续期 6 小时，连续 6 小时无通知才重新计数，已开过或已占用实盘开仓的同链 CA 永久不重开。

“停止计数”停止新信号计数和新买入触发，已有持仓的监控、平台保护单和成交查询继续运行。`/start` 仅展示菜单，`/count_start` 或“启动计数”才启动策略。策略状态会明确显示实盘模式与是否正在接收买入触发；旧模拟批次、旧指令和历史候选不会在升级后自动变成实盘买单。

通知包括：

- 开单已提交、成交已确认、失败与结果待核对；提交成功不等于成交。
- 止盈止损策略编号、条件参数、平台报告的执行/取消/失败状态，以及保护无法确认。
- 经过持仓余额验证的清仓状态；卖出金额和手续费不足时不编造最终净收益。
- 每 5 分钟的持仓价格摘要、关键涨跌幅提醒、缺价和恢复提醒。没有实际持仓时不发送持仓摘要。

默认只发送真实订单，模拟订单与止盈保护影子回放不混入实盘通知。独立持仓监控以已核验 GMGN 买入回执的美元成交价为涨幅基准。第三次通知实盘单优先使用与该买单钱包、CA、成交哈希和原子数量绑定的美元成交价；缺少时才使用成交确认后首个有效观察样本，并明确标注“相对观察基准”。随后补齐真实成交价会重算涨幅，已通知档位不重发。两种价格涨幅都不替代按成交数量、成本、卖出回执和手续费核算的账户收益。已过期、回退、成交前或来源不明确的样本不能建立基准。订单摘要间隔由 `TELEGRAM_SUMMARY_INTERVAL_SEC` 设置，默认 300 秒。

上涨档位为 **+50%、+100%、+200%、+500%、+1000%、+1500%、+2000%**。此后每增加 1 倍买入价提醒，即 22 倍（+2100%）、23 倍（+2200%）、24 倍（+2300%）等。同一持仓同档位去重，重启保留已提醒记录；一次跳过多档合并为一条通知。原下跌档位保留。

消息在发送时渲染为安全 HTML：标题和关键数值加粗、CA 和订单号使用等宽字体、匹配消息链与 CA 的 GMGN 详情链接显示为按钮，禁用网页预览。数据库继续保存纯文本，所有外部名称和内容均转义。

消息经 SQLite 队列持久化，已确认送达的事件不会因正常重启再次发送。429 遵守 Telegram 的等待时间；网络和服务故障退避重试；401/403 暂停发送并在系统页显示安全错误码。Telegram 没有消息幂等接口，极端情况下“平台已接收但本地确认未写入”可能重复送达，不能承诺恰好一次。消息发送串行限速，不阻塞下单的网络操作。

Telegram 默认通过独立的 IPv4 HTTPS 请求发送，保留证书验证、总超时和响应大小限制，不修改其他行情或交易接口的网络参数。此服务器使用 Node 默认 250ms 地址族切换时会过早终止 Telegram 连接；已用官方 API 验证 IPv4 连接可正常完成。

`/dashboard/api/overview` 的 `telegram` 显示配置、队列和最近送达状态，不返回 Token、Chat ID 或消息正文。`priceCapacity` 显示价格观察目标上限、每轮批量、真实订单优先观察数和开仓并发上限。

机器人订单中的未平仓资产现在优先进入价格轮询、Ave 订阅及链上池候选，不受扫描记录到期限制。这个范围不包括用户在其他平台自行买入、尚未导入订单系统的资产。当前观察目标上限 200，每轮最多 30 个，轮询完成后等待 15 秒；推送和备用价格源不构成每个资产的实时刷新保证。自动退出执行的就绪校验独立于价格观察与通知，不能用本功能绕过。

持仓现以 Ave `pricev2` WebSocket 为主要报价通道。订单状态更新立即调整订阅，持仓排在研究代币之前；重连恢复最新主题，停更的持仓主题通过 WebSocket 退订、重订恢复，并逐次退避。有效推送价格到来即计算涨幅档位，不等 HTTP 轮询。推送报价仍在有效期内时不再为该币发送 HTTP 查价；停更才使用批量备用查询，同币每 30 秒最多启动一轮补查，多条监控循环共用此限制，供应商的 429 冷却另行遵守。

报价健康独立持久监控：新持仓宽限 30 秒，持续断连或漏订阅 20 秒、已订阅报价超过 45 秒未更新时发一次 TG 提醒；收到新的有效 WS 报价后提醒恢复，HTTP 新价和心跳不会冒充推送恢复。没有持仓时不报警。系统状态的 `positionPriceStream` 显示主要通道、订阅数、报价更新时间、异常持仓和备用查询间隔。

已确认的独立接口测试买单由 `heldPositions` 观察器读取，使用持仓专用的 5 秒价格循环及实时推送，30 秒核验链上余额、60 秒读取 GMGN 保护状态。该观察器只查询已有持仓和订单，不执行开仓、平仓或撤单。

Telegram API 依据：[sendMessage](https://core.telegram.org/bots/api#sendmessage)、[请求规范](https://core.telegram.org/bots/api#making-requests)、[retry_after](https://core.telegram.org/bots/api#responseparameters)。
