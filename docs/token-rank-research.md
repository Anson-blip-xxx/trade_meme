# 代币榜单与钱包持续研究

“榜单研究”把既有 GMGN 代币涨幅榜、单币交易者快照和钱包买入记录关联起来，持续积累早入场与兑现利润的证据。原始记录仍保留在钱包研究库；新增模块只生成独立的派生研究库，不改变开单条件、评分或交易开关。

## 时间与盈利口径

每个代币保留首次本地记录的上榜时间，结合已留存的供应商通知时间与实际读到、含完整 CA 的 X 原帖时间比较买入先后。AI 叙事生成时间不能当作叙事诞生时间；没有原帖就显示未知。首次初始化会查找已有原始库中最早的有效上榜记录，避免历史回填顺序把近期记录误当成首次上榜。

买入证据必须绑定链、完整 CA、钱包、买入方向、完整交易引用及时间。当前交易引用来自供应商，不代表已经逐笔经 RPC 回执验证。供应商的 `start_holding_at` 是首次获得代币时间，也可能来自转入，因此只用于选择待研究钱包，不能直接证明首次买入。页面显示的是**采样记录中最早入场**，不是全链最早买家。

买入发生时间与系统获取该证据的时间分开保存。早于上榜、且买入证据在上榜前就已留存，标为当时已观测；上榜后才补查到早买，标为回溯补录。后者有研究价值，但不能据此声称系统当时已经预测到上涨。含 CA 原帖只提供时间线，不能证明钱包发现叙事的原因、与作者的身份关系或实际控制人。

盈利使用供应商单币累计快照，分别展示已实现、未实现和总利润；缺失值保持未知，不当成零。跨币汇总只取每个钱包在每个币的最新已知快照，不把重复采样累加。退出榜单采样窗口不能清除已积累的买入和利润，旧证据保留原采样时间并标明留存；取得有效新快照后再更新，包括转为亏损。盈利和亏损均纳入，并显示币数、已知盈利覆盖和快照时间范围。这不是钱包全部资产收益、统一时间窗口收益或经过审计的税后收益；没有完整成本依据，不计算投资回报率。

涨幅榜与盈利榜本身存在筛选偏差。跨币重复出现、早买后兑现以及前置钱包关联需要继续积累，单币高盈利不能直接升级为“聪明钱包”或增加自动交易权重。研究详情链接现有钱包档案和前置关联证据，保留进一步核验入口。

## 持续运行与容量

既有榜单采集沿用 GMGN 统一请求预算和限流冷却。候选研究兼顾供应商盈利排序与早期获得代币的线索，使用真实买入活动核验；不假设供应商提供“首次买入排序”接口。采集进度以独立、受限的游标状态保存到钱包库，重启不会每次回到相同头部钱包。失败和限流不视为调查完成。

本地关联计算在独立 worker 中运行，默认每 15 秒一轮、每轮读取最多约 500 条增量输入、计算最多 8 个代币。首次历史回填与新增记录并行推进，新证据、未完成历史样本和到期复查分别获得处理额度，空余额度可互补。历史发现扫描完成与逐币分析完成分开展示。每个代币的交易和交易者读取均有上限，截断时显示覆盖不足；不会把有限样本包装成全市场结论。原始库只读，派生库达到容量上限后保留已生成结果并报告容量错误。

页面读取独立输出库，不在 HTTP 请求中查询庞大的原始交易库。研究结果按版本保存，分页使用 `asOf` 固定视图，后来更新的盈利不会改变已打开的历史分页。不开页面也会继续运行；主页不会额外加载榜单和钱包完整列表。

配置示例：

```dotenv
TOKEN_RANK_RESEARCH_ENABLED=true
TOKEN_RANK_RESEARCH_DATABASE_PATH=data/token-rank-research.sqlite
TOKEN_RANK_RESEARCH_MAX_MB=512
TOKEN_RANK_RESEARCH_INTERVAL_SEC=15
TOKEN_RANK_RESEARCH_BATCH_SIZE=500
```

未显式设置启用项时，跟随 `WALLET_RESEARCH_ENABLED`；默认数据库路径跟随钱包库路径追加 `.rank-research.sqlite`。来源库、业务库和会话文件不能与输出库共用路径或文件。worker 不接收 API 密钥，不调用交易接口。

## 页面与接口

9528 页面新增“榜单研究”，提供“榜单代币”和“跨币钱包”两个视图，均默认每页 20 条，支持链筛选。钱包视图可按早入场次数或采样已实现盈利排序；详情保留具体代币、交易引用、时间比较、数据范围与 GMGN 跳转。

- `GET /dashboard/api/token-rank-research?chain=bsc&limit=20&offset=0&asOf=...`
- `GET /dashboard/api/token-rank-research/:chain/:address?limit=20&offset=0&asOf=...`
- `GET /dashboard/api/token-rank-research/wallets?sort=early&limit=20&offset=0&asOf=...`
- `GET /dashboard/api/token-rank-research/wallets/:chain/:address?limit=20&offset=0&asOf=...`

接口沿用工作台认证，只读，并校验链、地址、分页边界和时间。列表包含后台处理状态；历史回填未完成、来源缺失、容量不足或处理失败都应明确展示，不能把空白当成研究完成。
